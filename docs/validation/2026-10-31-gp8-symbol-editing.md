# GP8 parity E19: direct symbol editing and context menus (2026-10-31)

GP8 row E19: activate a displayed symbol and edit its existing value. Notes already select the inspector; this adds the title, tempo marks, chord names and clefs on the rendered score.

## Behavior
- **Double-click edits in place.** On the rendered score, double-clicking the title, a tempo mark (its `= 96` text, its metronome note, or its label), a chord name above a beat, or a clef opens a small editor beside it. Title, tempo and chord name are a one-line field (Enter applies, Escape cancels, the field is selected on open); a clef opens the five clef choices with the current one checked. A click that is not on one of these symbols behaves as before.
- **Right-click opens the actions that fit.** Title: Edit title. Tempo: Edit tempo, and Remove tempo change when the mark is not the initial tempo. Chord: Edit chord name, Open chord editor (the existing harmony dialog on that beat), Remove chord. Clef: the clef choices. Menus take arrow, Home and End; Escape closes.
- **Keyboard.** Shift+F10 or the Menu key, with the score focused, opens a menu of every action for the symbols at the edit target: the title, each tempo mark of that measure (the initial tempo when it has none) with Remove, the beat's chord with all three actions, and the clef of that staff. It opens beside the edit-target marker.
- **One edit per gesture, from existing edits.** Title: `setScoreInfo`. Initial tempo: `setScoreInfo`; any other tempo mark, and removing one: `setMeasureSettings`. Chord name: `setHarmonyChord` (a manual name; diagram and flags kept). Remove chord: `setHarmonyChord` with no chord. Clef: `setBarNotation` for that measure and staff. Undo takes back one gesture.
- **One optional field, replay-safe.** `setScoreInfo` gains `preserveOpeningMark` (TypeScript `edit-types.ts`, `engine.ts`, `parity-commands.ts`; Rust `edit_types.rs`). Absent, the edit is exactly what it always was (it rebuilds the opening mark as a plain one), serializes without the key, and replays old logs unchanged. `true` sets the title and artist and, for the opening mark only, sets its value, keeping its label, gradual change and visibility; a score with no opening mark keeps having none. The score-symbol title and initial-tempo edits use it, and the inspector's Apply score info sends it when the tempo field is unchanged, so renaming from the inspector no longer drops a tempo label or ramp. A tempo labelled or gradual at the start is therefore edited on the score, not refused.
- **Nothing recorded for no change.** Typing the current value, or choosing the current clef, closes the editor without an edit; a title or chord name with stray spaces counts as unchanged when typed back.
- **Refusals say why, before or with the text, and keep it.** A tempo outside 1 to 999 BPM, an empty, over-long or control-character chord name is explained under the field. A measure whose tempo marks or section `setMeasureSettings` cannot rewrite unchanged (a mark between beats, labelled or hidden, two on one beat, or a section marker with no text) is refused with a message and Remove tempo change is not offered; a mark at the start of an empty measure is fine. A chord with no diagram for the staff cannot be renamed here. The editor waits for the edit to land; if the document refuses it the editor stays with its text and says so.
- **Locked documents.** A finalized or password-locked score opens a menu instead of an editor: its message says why, every action is `aria-disabled` and none runs; the app's own handler refuses a stale edit too.
- **Busy.** The editor opens; Apply and the recording actions are `aria-disabled` through `busyGuard` (never `disabled`), the field keeps focus, and a status line says to wait.
- **Focus and lifetime.** The popover takes focus when it opens; Escape, Apply and a landed menu action return it to what had it. Pressing its padding, label or heading no longer moves focus to the score (which closed it and lost the text); clicking or tabbing elsewhere closes it without stealing focus. It closes unrecorded when the score, shown tracks, zoom, layout or page change, when the score area is resized by more than a scrollbar, or when scrolling (by hand or by playback following the cursor) carries it out of sight. A late-landing edit never closes a newer popover. It is re-fitted inside the scroller whenever its own size changes, so a growing error line stays visible.
- **Text.** All new strings are in `src/i18n` (`symbol.*`, 36 keys) in en, et and de; the lock message is the app's existing one.

## Limits
- **WebView2 and the Menu key.** The desktop run is the real app, but the Menu key (as opposed to Shift+F10) was not pressed in it; a native context-menu event on its key-up is suppressed in the popover but was not observed.
- **Text decides what a symbol is.** alphaTab reports no bounds for these symbols, so a click is resolved from the clicked `<text>` characters (and, for chords, that it is centred) and the bounds of the measure under it. Beat text or a lyric spelled exactly like a chord name in a measure with that chord opens the chord; an artist line equal to the title opens the title; an empty title cannot be clicked (use the keyboard menu or the inspector). A mark that overhangs into the next measure is attributed to that measure. The chord diagram heading is not a target. In the real app a chord name sits just under the tempo mark and the tempo text's box overlaps its top, so a click on the chord's upper edge can open the tempo editor.
- **Clef is per measure.** `setBarNotation` changes one measure of one staff, so the next measure shows its own clef again; the menu names the measure.
- **Renaming a chord changes that beat only.** `setHarmonyChord` gives the beat its own chord, so other beats that shared the old chord keep their name.
- **Not offered here.** Rewriting a measure whose tempo mark is between beats, labelled, hidden or beside a marker-only section stays in the inspector's Measure panel; a chord that carries only a name (some imports) is renamed in the chord editor.
- **Page-layout hit path.** The paper-layout branch is checked by hand in a browser and in the desktop run's default layout only; no automated test covers it.
- **Closing on resize** compares with the area when the popover opened and tolerates 24 px, so a very small resize does not close it.
- The lock message is English because it is the app's existing constant. Fixture tests that read `.analysis/compatibility` fail here with ENOENT, as expected for a worktree.
