## Intended result

The musician can choose Vertical page, Horizontal page, Grid, Parchment, Vertical screen or Horizontal screen in the existing score toolbar, retain the displayed tracks and editor selection, and use manual fractional 25–300% zoom, Fit width or applicable Fit page. Layout is a per-document view preference. It must not change music, print settings, revision, dirty state, undo history or native audio preparation, position, range or loop.

The six names come from the retained public manual, `.analysis/parity/public-manual-pages.txt:1116–1130`. Actual GenAI references under `docs/design/reference-workstation/` (removed before publication: images and provenance records) establish the compact charcoal shell, cream notation, restrained blue emphasis, control placement and page arrangements. Root must inspect and record the selected PNG/provenance pair for each mode before UI implementation. Generated musical content, labels outside this toolbar, paper proportions, duplicate cursors, page numbers and overlap are incidental; preserve the real app's content and validated paper geometry. No unrelated shell redesign, inspector changes, export headers/footers or instrument-view changes are included.

Assumptions: default to Parchment for old views to retain authored system layout; do not force existing authored breaks into automatic screen wrapping on migration. Paper dimensions/margins come from App's validated effective page layout, including its current invalid-setting fallback. Physical pages may be portrait, landscape or custom according to those settings; the mockup's portrait paper is an example. Fit favors legibility within the existing 25–300% zoom range; a limit is stated visibly instead of pretending that clipped paper fits.

## View contract and modes

Add an optional `DocumentViewState.scoreDisplay` with exact fields `{layout, zoomMode}`. Shared TS enum unions and matching Rust camelCase enums contain:

- `layout`: `verticalPage`, `horizontalPage`, `grid`, `parchment`, `verticalScreen`, `horizontalScreen`.
- `zoomMode`: `manual`, `fitWidth`, `fitPage`.

Missing preference means `{layout:'parchment',zoomMode:'manual'}`. Preserve omission through untouched old view repair/serialization, including the current exact initial view shape. Rust uses a defaulted optional field omitted when absent; missing or null is absence. Preserve strict unknown-field rejection for a supplied object and existing envelope. Frontend repair drops malformed objects, including null and arrays; valid layout with `fitPage` in an endless mode normalizes to `fitWidth`. Native accepts valid enum pairs as view data through ordinary serde derives, including serde's positional two-value sequence representation, and serializes named fields. No custom deserializer or broader native shape hardening is included. Frontend resolution owns applicability, with no native audio behavior.

Keep the existing numeric `zoom` as the last manual percent. Only user preference/manual edits update view state. Derived fit percent, dimensions, page origins, cursor state and resize callbacks never call `onViewChange`. Switching documents restores preference and manual zoom; save/reopen/recovery old views remain usable. No project/edit/IPC command is added: the existing view bridge carries this optional field.

|---|---|---|

Tracks, notation, page geometry or base engraving density may repaginate; zoom, fit and grid resize only change presentation. ## Geometry, extraction and interaction

Collect eager SVG render-result strings per generation, explicitly choosing SVG output. Match finished systems to chunks by public bar interval and geometry, with unique association and only justified SVG rounding tolerance. Account for leading title/tuning/chord blocks and trailing annotations in the page content; no dropping, duplication, splitting a system or invented export text. Pack the union of each chunk and its real/visual bounds, preserving its original offset inside that union. The actual probe found11.3px of top-padding whitespace extending beyond nominal later chunks; this is not clipping tolerance. Preserve equivalent SVG overflow/font styling for subpixel viewport truncation, and verify actual ink separately. Real paper content height is paper height minus top/bottom margins. An indivisible block too large for the configured paper yields an actionable unavailable state explaining that fewer displayed staves, a different page size or smaller print scale is needed. Never clip it, shrink only that block or draw false page boundaries.

Keep one mounted, nonzero-width, hidden-from-accessibility, noninteractive source renderer for physical modes. Its independent fixed usable width must not enlarge the visible scroll area. Do not use display:none or depend on offscreen lazy loading. Capture eager chunks initially; no virtualization framework. Bound memory and representative-score cost in the probe/actual checks and report a limitation if needed. If configured paper cannot contain a whole block, show the actionable page error and the continuous live source as an explicit fallback; retain the desired preference for retry after tracks/paper change, disable unavailable page fitting and show the last manual magnification. Never present this fallback as successful page fit.

One map connects renderer coordinates to each displayed system and inverse pointer hits. Include paper margins, host padding, borders, scroll offsets, sheet gaps and current display factor exactly once. Gutters and blank margins have no note hit. Original bounds remain immutable. Select the actual public rendered staff/bar by Y, then beat/note/voice by public bounds; the library's master-bar lookup alone can pick the wrong displayed staff. Distinct actual notehead hits take priority. For coincident visible objects, prefer the current edit lane/voice when it belongs to that clicked staff, then lowest voice/note index as a deterministic fallback; geometry cannot inherently distinguish identical noteheads. Canonicalize with current source/projection object identity.

Use shared local selection actions for both source API events and mapped physical events: ordinary note/beat selection, Shift range, Ctrl/Meta note toggles, triple-click track, cross-system/page drag and range-handle resize. Map edit caret, note markers and range highlight blocks through the same geometry; do not draw a selection rectangle through a blank page gutter. Maintain focus, edit announcement and caret reveal. No synthetic private API mouse events or applyPlaybackRangeFromHighlight call.

## Playhead, highlighting and lifecycle

Public customCursorHandler supplies existing clock-derived bar/beat bounds, interpolation endpoints and duration. Map these to the visible page, cancel transitions across system/page boundaries or layout generations, and retain the correct stopped/mid-beat cursor. Do not introduce another timing loop. Public customScrollHandler reveals the mapped target in the same real scroll host in both axes and is disposed normally. Keep the existing native clock, speed and occurrence/repeat semantics. Install a stable handler once across modes: construct with cursor creation disabled, install the handler, then enable cursors through public settings before the first score render. This avoids the pinned setter's incoming-onDetach behavior when cursors already exist. Endless modes retain source cursor placement through public IContainer operations; physical modes also paint mapped app-owned cursors. Do not repeatedly reassign handlers to repaint.

Preserve element highlighting. A per-instance decorator may wrap only public `uiFacade.highlightElements(groupId,masterBarIndex)` and `removeHighlights`, forward original this/arguments/return behavior, and mirror those supplied opaque IDs into current derived SVGs. Do not derive private beat-group names or access private maps. Capture current-generation active IDs until React mounts matching chunks. Preserve prior method ownership and restore only this adapter's still-installed wrapper before API destroy. No prototype patch or MutationObserver subsystem.

Render-start invalidates maps, overlays, pending active IDs and transitions. Queued old callbacks must be rejected by current bounds/score identity, not merely current API score. The facade decorator shares the accepted cursor generation token. Cache valid public cursor arguments and repaint locally when the completed current map mounts; postRenderFinished queues the library's forced cursor update before notifying app listeners. Replaying a running transition preserves its elapsed position/duration rather than restarting its old beginning; no timer, native updatePosition call or tick/time setter is introduced. Test stale chunks, cursor callbacks before mount, rerender/mode switch, score/projection replacement and destroy/remount. Layout-only changes use settings update/render rather than reload score/MIDI when object identity and tracks are unchanged; native load/seek/range/loop calls must remain absent.

## Toolbar and fit feedback

Use the generated placement above notation, keep visible-track controls and compact responsive wrapping. Fit buttons expose their selected state with aria-pressed. Fit page is disabled in endless modes and associated with a visible concise explanation, `Fit page is available in page layouts.` Numeric manual entry retains finite fractional 25–300 validation, reset-on-blur and busy guards; a valid user entry exits fit. Preserve the manual number while displaying the derived zoom separately during fit so a resize cannot overwrite manual state.

Measure the actual score scroll host, including computed padding, border/scrollbar effects and dock/pane resizing. Fit width ratio is available width / natural target width; Fit page is min(width ratio,height ratio). Clamp derived fit to25–300%, and show an accessible status when limited: `Fit is limited to 25%. Scroll to view the full score.` or the corresponding300% message. No repeated render/resize feedback loop. A physical paper target must include its visible border in fitting. Vertical-screen fit starts at100% reflow and only reduces for an oversized base-scale measure; horizontal-screen fit measures its base-scale strip. Retain the base measurement for the current score/tracks/host geometry and perform at most one final fit render, never derive a new ratio from already fitted output. Do not claim clipping-free full fit when a limit applies.
