# GP8 parity T28: wah open/closed gestures (2026-10-22)

GP8 lets users mark a beat with an open (`o`) or closed (`+`) wah gesture. This slice adds `wahPedal` to the patch of the existing replayed `setBeatGestures {target, patch}` command. The values are `0` None, `1` Open and `2` Closed, matching alphaTab's `WahPedal`. It was implemented on branch `feat/gp8-parity`.

## Behavior
- **Engine (`src/editor/gestures.ts`):** `wahPedal` sets or clears the beat's wah gesture. Like tap, slap, golpe, rasgueado and barre, it is refused on percussion and notation-only staves, which clipboard conversion cannot carry. Undo replays the shorter history.
- **Rendering and export:**
  - alphaTab draws the wah mark above standard notation.
  - GP export writes `<Wah>Open|Closed</Wah>` and re-imports it.
  - MusicXML export refuses the gesture with a clear error, as it does for golpe.
- **Validation:**
  - TS and Rust accept `0`–`2` and refuse anything else, including `-1`, `3`, `null`, fractions, strings and booleans.
  - Pasting from the clipboard now range-checks the beat's wah value, so an invalid clip can't put an unnamed wah into a GP export.
- **UI:** Beat notation has a Wah pedal choice (None, Open, Closed), which is disabled on staves that aren't stringed. Apply beat gestures sends only the changed keys.

- **Frontend:**
  - `gestures.test.ts`:
    - Open, Closed and None on a beat;

    - invalid values leave the score untouched;

  - `GesturePanel.test.tsx`: the Wah pedal options, its starting value, and an exact `{wahPedal:2}` patch.
  - `notation-commands.test.ts`: the project envelope with wah, and invalid wah values refused.
  - RED log: `.analysis/parity/wah-red.log`.
- **Native:** `edit_types.rs` gesture tests cover the full payload with `wahPedal`, every valid value `0..=2`, and refused values. `cargo test --lib` passes (269) and `tests/protocol.rs` passes.
- **Desktop (Windows desktop-test build):** `tests/desktop/parity-wah.mjs` opens the four-track fixture, opens Beat notation, chooses Wah pedal Closed and applies it. It asserts:
  - the recorded edit;
  - that a GP export reloads exactly one wah, on `Guitar9:0:0` with Closed;
  - that Undo clears it;
  - that there are no page errors.

  This run was made before the review fixes, which only add refusals for staves that aren't stringed and range checks on paste.
- **Review:** an Opus adversarial review asked for minor changes, all fixed with tests:
  - the percussion and notation-only policy, matching clipboard conversion;
  - TS tests for invalid saved values;
  - the clipboard wah range check;
  - an Open re-import test.

## Limits
- T28 is partial. The wah gesture is a score mark with no sound. GP8 plays wah through its wah effect and automation, tracked as A13 (no wah DSP yet).
- alphaTab draws the mark only on standard notation, so it is hidden on staves that show tablature only.
- No original-GP8 side-by-side comparison was made.
