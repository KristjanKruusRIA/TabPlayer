# GP8 parity F06: Power Tab (.ptb) import

Date: 2026-10-31. Status: **experimental and partial; verified only against synthetic fixtures. Not tested on any real Power Tab file.**

## Behavior

- **Entry point.** `.ptb` is added to the Open dialog filter (`src-tauri/src/lib.rs`). Rust's existing intake (`src-tauri/src/intake.rs`, after merging `develop`) reads the file with its stable bounded read and stages the original bytes as a `file` base document, so the original is preserved in `.tabplayer` projects. `intake.rs` additionally refuses content that starts with the `ptab` signature and exceeds 16 MiB, whatever the extension (a Power Tab file renamed `.gp` is capped too). The window-side file check (`archive-gate.ts`) skips the alphaTab worker probe for `ptab` bytes, because alphaTab cannot read them; the bounded Power Tab reader checks them when the document is built. The library index, folder scan and batch converter do not list `.ptb`.
- **Conversion.** `src/engine.ts` detects the `ptab` signature in the stored bytes and converts with `src/import/powertab.ts` (untrusted-input reader) and `src/import/powertab-score.ts` (builds an alphaTab `Score`). alphaTab 1.8.4 has no Power Tab importer, and neither alphaTab nor the existing GP/GPX import path was changed. Conversion runs in `buildDocument` before the document is committed, so a failed import leaves the current document untouched and shows the error banner.
- **Intended versions:** Power Tab 1.5 and 1.7 songs (unconfirmed against real files). Version 1.0/1.0.2 files and lesson files are rejected with a specific message.
- **Imported:** title, artist; guitar score and bass score tracks (the bass score only when it has notes and the same total measure count as the guitar score; its own system layout may differ, and a bass score that cannot be converted is dropped with a notice instead of failing the import); per-guitar name, MIDI preset, capo and tuning, chosen per staff by the first GuitarIn assignment (staff guitar bitmask taken from the high byte of its data word, as in Power Tab Editor) (later changes are reported as dropped); composer, lyricist and copyright; measures, time signatures (including common/cut), key signatures (major/minor), repeat starts and ends with counts, double bars, rehearsal letters as sections; tempo markers (standard, converted to quarter-note BPM, snapped to the measure start); positions with note length, dots, rests, tuplets (irregular groupings), a second voice; fret/string notes; ties, hammer-on/pull-off origins, dead and ghost notes, natural harmonics, vibrato, palm mute, let ring, staccato, grace notes (as zero-length grace beats), and 64th notes.
- **Dropped, and reported in the app.** After a successful import a status banner lists what was not imported with counts: lyrics text, arranger/transcriber/note fields, chord diagrams, text boxes, guitar changes after the first per staff, dynamics, alternate endings, directions, chord names, rhythm slashes, arpeggios, pick strokes, accents, tremolo picking, tapping, triplet-feel marks, fermatas, slides/bends/trills/artificial harmonics, tremolo bars/volume swells/multi-bar rests, octave marks, free-time barlines, listesso/pace tempo markers, unsupported note lengths or time signatures, notes on missing strings, and a bass score that cannot be aligned or read. Tracks beyond the 15 free playback channels are also dropped and counted. Guitar volume, pan and effect settings, fonts and page layout are never read and are not counted individually. Objects of an unrecognised kind cannot be counted, so "nothing dropped" means "nothing recognised was dropped".
- **Limits against hostile input.** 16 MiB file, 32 guitars, 4096 systems, 8 staves per system, 256 barlines per system, 1024 positions per voice, 16 notes per position, 4000 measures, 100 000 positions and 60 000 notes per file (checked while reading, before any score is built), 12 000 bars (tracks x measures) and 150 000 beats per score, 64 KiB strings. Exceeding a size limit gives a "too large to import safely" error, not an engine failure. A synthetic at-limit file (3 tracks, 3870 measures, 0.1 MiB) imports in about a second. Every declared count is checked against the bytes that remain before it is used. There is no recursion. Every failure is a `PowerTabError` with a user-readable message; unexpected internal errors from conversion are wrapped the same way.

## Review

Two independent review rounds found and I fixed: 16-bit beaming and bootleg dates, a bass layout `TypeError`, memory exhaustion from large track, measure and note counts, grace-note overfill, GuitarIn handling (twice), lost metadata, 64th notes, and the renamed-file size limit. The final state has had no further independent review, so treat it as unreviewed.

## Limits

- **No real Power Tab file was tested.** The binary layout was reconstructed from the public Power Tab Editor project's published reader behaviour (read as a description, via summaries; no code copied into this repository) and the fixtures are written by a writer in `src/import/powertab-fixture.ts` that encodes the same assumptions. The tests prove self-consistency, not agreement with files produced by Power Tab. Several widths and enum values were inferred rather than confirmed: release-type sub-fields in the 1.7 header (audio year as 16 bits; bootleg month, day and year as three 16-bit values), author-type values, the width of boolean and colour fields in font settings (skipped as 3+4 bytes), the position of each class header in vectors, tuning note byte order (reversed when ascending), the position `beaming` field (taken as 16 bits from the published reader after review; its bit meanings for tuplets are inferred), and the barline-to-measure assignment. Any real file that deviates fails with an error or imports incorrectly. A first real-file test is required before claiming support.
- Tempo changes snap to the start of their measure. Free-time bars, 1.0 files, lessons, 2.0 `.pt2` files and `.gp`-style export of PowerTab-only data are out of scope.
- Fonts, chord diagrams and all dropped items above are lost on import and in any later export; the native project keeps the original `.ptb` bytes.
- **Licensing.** Power Tab Editor is GPL-licensed. No code or tables from it were copied; the importer is an independent implementation written from a prose description of field order and widths. The format itself is not covered by that licence, but anyone redistributing should re-check before bundling real Power Tab samples.
- Not verified: macOS and Linux behaviour, the desktop shell open dialog with `.ptb`, library/workspace restore of a saved Power Tab project in the real app, and playback of an imported score through the native audio plan.
