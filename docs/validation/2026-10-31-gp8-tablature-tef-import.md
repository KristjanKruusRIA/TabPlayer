# GP8 parity F07: TablEdit (.tef) import

Date: 2026-10-31. Status: **experimental and partial; verified only against synthetic fixtures. Not tested on any real TablEdit file.** This replaces the rejected attempt on `feat/slice-f07` (commit 6788db7), whose parser invented the format; none of its code is reused.

## Behavior

- **Entry.** `.tef` is in the Open dialog filter (`src-tauri/src/lib.rs`) and in the drag-and-drop whitelist (`file_library/commands.rs`; `.ptb` was missing there too and is added, with a test). Rust intake stages the original bytes as a `file` base document. `intake.rs` caps content at 16 MiB by signature (`ptab` at byte 0, or `tbed` at 0x38) whatever the extension. The window-side check (`archive-gate.ts`) skips the alphaTab probe for TablEdit bytes, keyed on content, so Open, drop and project restore all reach the importer. `engine.ts` converts in `buildDocument` before the document is committed, so a failed import raises an error with no state change.
- **Shared code.** `src/import/import-support.ts` holds the bounds-checked `ByteReader`, the 16 MiB limit and the `ImportReport` (merged dropped counts and a bounded warning list that counts overflow instead of discarding it). The Power Tab reader now extends the same `ByteReader` and uses the same label formatter.
- **Imported:** title, subtitle, copyright; tempo; per-measure time and key signatures; pickup measures (anacrusis flag); one track per instrument that has notes (name, MIDI program, tuning, bass clef for low tunings); notes, chords, rests, dotted, double-dotted and triplet lengths, 64th notes; ties; grace notes (as a grace beat of the stored grace fret); a second voice; simple repeats from the reading list.
- **Strings.** String 1 is the highest-pitched string (top tab line). Pitch is `96 - stored value`, stored lowest string first. Not inverted; a test pins E4 on string 1 and E2 on string 6. Bends are not imported at all (nothing is read, so nothing is halved).
- **Capo.** The stored capo is read but not applied: MuseScore's reader uses only the stored tuning for pitch, and applying the capo as well sounded every note too high (E4 with capo 3 gave 67). It is reported as dropped. Whether the stored tuning already includes the capo is unknown.
- **Dropped, reported in the notice with counts:** text markers and texts, comment/notes/link fields, fingerings, grace-note effects, events of unrecognised kind, events after the last measure or on undefined strings, notes that overflow their measure, notes shifted later by an overlap, duplicate notes, ties with no earlier note, unsupported time signatures, key signatures or lengths, capo settings, unreadable text fields, reading-list jumps and endings, repeats that overlap or exceed the expansion limit, instruments with no notes, instruments beyond 15 playback channels. The notice says the import is experimental. "Nothing dropped" means "nothing recognised was dropped".
- **Limits against hostile input.** 16 MiB file; 1000 measures; 16 instruments; 12 strings each; 10 000 events (counted while reading, before building); 2000 reading-list entries; 3000 bars (tracks x measures) and 30 000 beats built. Events are bucketed per measure by binary search, so conversion is linear (the earlier version took 23 s on a 1.2 MB file). Conversion runs on the window thread without a Worker deadline, which is why the caps are low. **Repeats:** only runs of one identical range in order become repeats, never nested or overlapping, count capped at 16, and the total played cost (notes plus rests, counted once per pass) is capped at 50 000, because the audio engine spreads its note list into one call and a 248 KB, 20 000-event file (one track, 12-string chords, a 16-fold repeat) overflowed it with a RangeError in the plan Worker, so the playback plan stays bounded; `rebuildRepeatGroups()` is called after they are set. Every table count is checked against the bytes that remain before use. No recursion. Every failure is a `TablEditError`. Any playback-plan failure is also given a readable message (`src/audio/plan-error.ts`, used by `plan.worker.ts`).

## Layout facts and provenance

Sources: **M** = MuseScore `importexport/tabledit` reader (`importtef.h`, `importtef.cpp`, `measurehandler.cpp`, `tuplethandler.cpp`, branch `deprecated_master`, GPL). It was read, through fetched text summaries, for layout facts only; no code, tables or structure were copied, and this importer is written independently. No published TablEdit specification was found (web search found only user help pages). Because M is a single source, "confirmed" means "stated by M", not verified against real files.

| Fact | Status |
|---|---|
| No magic at byte 0; u32 `tbed` (bytes `tbed`) at 0x38; the marker is sometimes byte-reversed | confirmed by the header struct comment in M (`importtef.h`: 'sometimes byte-reversed'); M's reader code does not compare it, so the location 0x38 comes from the review brief. Both byte orders are accepted (here and in `intake.rs`); whether the rest of a reversed file is also swapped is **unknown**, and it is parsed as little-endian |
| Fixed header: tempo u16 at 6 (quarter-note BPM), security code u32 at 16 (non-zero = refuse) | confirmed (M) |
| Pointer table (u32 absolute offsets): contents 0x3C, title 0x40, subtitle 0x44, comment 0x48, notes 0x4C, texts 0x54, measures 0x5C, instruments 0x60, reading list 0x80, link 0x84, copyright 0x8C; zero = absent | confirmed (M) |
| High byte of the u16 format word at 0xCC must be 10 (TablEdit 3.x) | confirmed (M) and the only version gate; the word at 0xCA is **not** checked (M does not test it) |
| Text: u16 size including terminator, `size-1` bytes, terminator | confirmed (M); size 0 treated as empty |
| Measures table: u16 structSize, u16 count, u32; 8-byte records: flag (0x08 = pickup), unused, i8 key, size, denominator, numerator, u16 margins | confirmed (M) for offsets; denominator is the literal value (4 = quarter): **guessed** (M does not say, a log encoding would break it) |
| Instruments table: u16 structSize, u16 count; 68-byte records: u16 strings (1..12), u8 MIDI voice at +8, u16 capo at +12, 12 x u8 tuning at +20, 36-byte name at +32 | confirmed (M); stride is `max(68, structSize)`: **guessed** |
| Tuning value `v` means MIDI `96 - v` | confirmed (M); the instrument capo field is read by M but not applied to pitch, and this importer follows that |
| Strings numbered globally across instruments; within an instrument the tuning entry is `strings - i - 1` | stated by M; **the reading that string 1 is the top line, i.e. last stored value, is inferred** (TablEdit's convention plus M's index arithmetic). If a real file shows otherwise, the fix is one line in `tabledit.ts` |
| Reading list: u16 structSize, u16 count, entries u16 first, u16 last + label | confirmed (M); that measure numbers are 1-based and inclusive, and that identical consecutive entries mean a repeat, are **guessed** |
| Contents: entries of a u32 word plus 8 bytes, ending at `0xFFFFFFFF`; word >> 3 = slot, position = slot / totalStrings (64ths of a whole note), string = slot % totalStrings | confirmed (M) |
| Entry bytes: b1 low 6 bits marker (1..0x32 note with fret = marker-1, 0x33 rest, 0x39 text marker), 0x40 grace flag; b2 low 5 bits duration code, `b2 >> 5 == 7` tie; b3 bits 0x30 voice (2 upper, 3 lower); b4 grace effect (>>5) and grace fret (low 5); b7 fingering | confirmed (M) |
| Duration codes: 0..18 cycle plain, dotted, triplet over whole..64th; 19, 22, 25, 28 double dotted half..16th | confirmed (M) |
| Triplets: a triplet beat is a 3:2 tuplet of its base value; **positions around triplet groups, and the stored position step, are guessed**. M notes TablEdit stores a triplet with a different nominal length than its true one, which this importer cannot resolve without a real file, so it ignores position gaps inside a triplet group and fits each bar to its time signature |
| Voice mapping (default and upper to voice 1, lower to voice 2) | guessed |
| Pickup measure: leading gap removed, no trailing rest padding | M describes the gaps; the rendering is guessed |

## Evidence

- `src/import/tabledit.test.ts` (25 tests, passing): parsing, content-keyed detection, refusals (wrong marker, protected, old version, 0/13 strings, no measures, missing sentinel, pointer outside file), truncation at every byte offset, 1500 corruption rounds that never touch the `tbed` marker and are asserted to get past the signature (more than 300 parse fully) plus 300 random-garbage rounds with a valid marker, huge declared counts, event and bar/beat caps, string orientation and pitch, instruments, rhythm, bar filling, dotted/triplet lengths, grace/voices/64ths and dropped-content counts, reading-list repeats and jumps, exact repeat playback order from real MIDI generation, a small file with nested and 600-fold repeats whose played bars stay bounded and whose playback plan builds, the largest allowed file (10 000 events, 3 tracks, repeats) importing and building its playback plan in a few seconds, capo not doubled, overlap reporting, pickups, merged bounded notices, the empty file, `buildDocument` integration, a bad file raising an error, and the archive-gate skip (no Worker created).
- `src/import/powertab.test.ts` (25) still passes after sharing the reader.
- `npx tsc --noEmit` passes. `vitest run src/import src/interchange/archive-gate.test.ts --testTimeout=40000 --maxWorkers=2`: a wider run over `src/interchange` and `src/engine` showed only `ENOENT` failures for `.analysis/compatibility` fixtures that are absent in this worktree (GP and MusicXML suites); those suites were not exercised against real files.
- `cargo test --locked --lib intake` passes (12 tests, including the new TablEdit cap) and `drop_tests` pass (4, including `.ptb`/`.tef`), with empty stand-in `resources/audio` and `resources/library` directories created for the build and removed afterwards.
- **Real files, 2026-10-31.** All 60 `.tef` test files from MuseScore commit 32f0a26 (`.analysis/tef-corpus`, not committed) open without an error. `src/import/tabledit-corpus.test.ts` pins meters, keys, tuning, title and rhythm on them and skips where the files are absent. They exposed one real defect: files declare 12 in the measure table header but store 8-byte records, so every measure after the first was misread (wrong meter, stray keys and pickups). The reader now always uses 8 bytes, and the synthetic fixture declares 12 like real files do.
- 28 of the 60 were inspected against what their file names describe: rhythm, dots, triplets, rests, chords, ties, grace notes, tunings, repeats and titles match. This is a reading of names, not a comparison with TablEdit or MuseScore output.

## Limits

- **Small sample files only.** The 60 real files are short test pieces written for MuseScore's importer. No full-length score from a TablEdit user was opened, and no output was compared with TablEdit itself.
- `voices.tef` still reports dropped notes (9 overflowing a measure, chord notes of unequal length), so music with more independent voices than the two supported loses notes; the notice says so.
- The layout comes from one third-party reader, learned through summaries of its text, not from a specification.
- Zip-compressed `.tef`, TablEdit 2 files, big-endian files, protected files, `.tbt`/`.ptb`-style sibling formats are out of scope.
- Texts, chord diagrams, effects (bends, slides, harmonics, etc.), dynamics, repeats beyond simple ones, endings and page layout are not imported; the native project keeps the original bytes.
- **Licensing.** The MuseScore reader is GPL. Only facts about the file layout were taken from it; no code or structure is copied. The format is not covered by that licence. The MuseScore test files are not committed or redistributed here.
- Not verified: macOS and Linux, the desktop open dialog and drop with `.tef`, restore of a saved TablEdit project in the real app, playback of an imported score through the native audio plan, library index or batch converter (they do not list `.tef`).
