# UI redesign phase 3: the app shell and the transport (2026-10-31)

Branch `worktree-agent-ab86a7258a80ec5c5`, from `develop`. Scope: the top bar, the panel layout and how the left task area, dock and playback controls are reached, and the transport bar. The rig, mixer, instruments, dialogs and editing panels are unchanged. Native playback is still the timing authority; `src-tauri/src/audio/tone.rs` and all Rust are untouched.

## Behavior

**Palette and type.** The shell moves onto the same warm charcoal, lime and blue tokens as the rig and mixer (`--tp-*`), in Instrument Sans with IBM Plex Mono for clocks and numbers. The `--ws-*` names stay, now defined from `--tp-*`, so the panels that still read them (track settings, sound panel, master, overview, waveform, recovery) take the new colours without edits. Lime means playback and "on"; blue is focus and selection. The legacy navy rules for the inspector and instrument dock were overridden.

**Top bar (40 px).** Left: the app mark (six tab lines and one fretted note), File, View, Undo, Redo. Centre: the Score, Sound and Mixer switch, centred on the window by a three column grid. Right: three panel toggles (track panel, inspector, bottom dock; `aria-pressed`, same state as the View menu checkboxes), Help and the document name. Under 1180 px Undo and Redo show their glyph only and the name moves to the document tab; their accessible names stay.

**Transport (bottom, above the status bar).** One row of captioned groups, divided by rules: Play and Stop; Bar n of N with a large clock; Loop bars with start and end fields and the Loop toggle; Click (Metronome toggle); Speed with Slower, the percent and Faster, and the BPM in the caption. Loop, speed and the metronome were hidden or a dropdown before; the loop fields were two clicks away. Only Seek, completed passes, the metronome pulse and the occurrence-aware Selected playback stay behind More playback, which now opens upward. A hairline scrubber on the transport's top edge shows how far playback is and seeks to a bar on press, arrow keys step a bar, and a drag sends one seek on release. Under 1181 px Stop and Metronome show their glyph only.

**Left task area, dock, rail.** Track, Sound and Backing and the dock's Overview, Mixer, Instrument and Backing are underlined tabs (blue line on the open one) instead of boxed buttons. The narrow rail (under 1180 px) is 64 px wide with a blue edge on the open pane. The score tools strip is a grid: display mode, tracks, zoom, fit and visible tracks wrap in one flow beside Show instrument and the measure count, so it takes 63 to 95 px where it took about 120.

**Every function stays reachable.** No control was removed: File, View (checkboxes, input preferences), Undo/Redo, Help, the palette, every dock and pane switch and every transport control keep their roles and names, except Speed (below). `aria-keyshortcuts="Space"` is still on Play. Space on the score still plays and pauses.

**Changed names, for the drivers.** Speed was a `combobox` named "Speed"; it is now a group named "Speed" with buttons "Slower" and "Faster" that step through the same preset list (10, 25, 50, 75, 100, 125, 150, 200, 250, 300 and the current value). The clock was `0:01 / 0:06 · M1` in one `output`; it is `output.transport-time` ("0:01 / 0:06") plus "Bar 1" in the group's caption. Loop start and end are visible, not under More playback (`revealPlaybackControls` still works).

**Invariants.** Busy: Play (when not playing), Loop, Slower, Faster, Seek, the scrubber and Metronome use `busyGuard` or `aria-disabled` plus a refusing handler, so a focused one keeps focus (tested). Pause and Stop stay available while busy. `disabled` remains only for "not ready" (the fieldset) and "no cursor choice yet".

## Review

Self-review only; no independent reviewer was run (this task did not allow spawning one). Checked against the invariants: no timing, audio or Rust change; busy handling uses the shared guards; shortcut handling in `selectionKeys` is unchanged and was driven; layout holds at the four widths and 1280x700. Things found while reviewing and fixed: Play's non-busy `disabled` kept for "no cursor choice" but busy now `aria-disabled`; the legacy `.transport output { min-width:135px }` rule in `styles.css` would have stretched the new outputs and was removed with the other dead `.transport` rules; the old `.score-tools` grid rules in `styles.css` are overridden rather than deleted. No hot path (auth, permissions, crypto, guards, migrations, CI, production config, dependencies) was changed.

## Limits

- **Not run in the desktop app.** The browser harness uses a fake native boundary, so no sound was played, the scrubber seek and Slower/Faster were not heard or measured on the real engine, and the updated `tests/desktop` drivers (`setPlaybackSpeed`, the clock reads, the popover geometry) have been syntax-checked but not run. WebView2, and the WebKit engines on macOS and Linux, were not tested; the scrubber styling uses `-webkit-` slider pseudo-elements, which both use.
- **The whole suite was not run to completion.** Two attempts on a shared, loaded machine stalled (the second finished 4 of about 290 files in 15 minutes, with `src/compatibility.test.ts` failing 7 of 8 for the missing `.analysis/compatibility`). The two groups above are the files that render the shell, the transport or the panels that read the shell tokens; the rest were not re-run.
- **Plan fixtures:** failures in `src/audio/plan.test.ts` from the missing `.analysis/compatibility` are expected in a worktree.
- **Short windows are tight.** At 960 x 600 the score paper is 186 px high (the chrome is top bar 40, tabs, score tools 95, dock 144, transport 57, status bar). The score tools strip is the existing `TrackDisplayControls` markup, only restyled; its "Fit page is available in page layouts." line still takes a row at 960.
- **Not redesigned:** the contents of the Track, Sound and Backing panes, the inspector, the document tabs and the File menu list (it has no separators). Panels that read `--ws-*` were checked only in the views captured (Track, Sound, Backing, overview, mixer, instrument dock); the backing waveform dock and the recovery prompt were not looked at after the token change.
- **Speed:** the stepper moves through presets only; an arbitrary percent (for example 85) cannot be typed. The old dropdown could not either, but a custom value set by the Practice panel is kept in the list and steps from there.
- **Two "Backing" and two "Sound" labels** still exist (left task tabs and dock or view switch); names were kept for the drivers.
- Full text zoom and touch were not tested.
