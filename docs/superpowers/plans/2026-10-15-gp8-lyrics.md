# Guitar Pro 8 Lyrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The user has already selected parallel feature workers; root coordinates shared integration.

**Goal:** Deliver raw per-track lyrics with five independent line starts, deterministic syllable placement, native history, and proven standard visible GPIF interchange.

**Architecture:** A focused lyrics editor owns raw source and derived Beat.lyrics placement. An ephemeral Track cache survives root-controlled rebuilds while exact source persists in finite native commands and standard GPIF Track lyrics. Root integrates schemas, replay hooks, selection/export, and UI composition.

**Tech Stack:** Rust/Tauri, React/TypeScript, alphaTab1.8.4, fflate0.8.3, DOM XML, Vitest.

**Spec:** [Guitar Pro 8 lyrics design](../specs/2026-10-15-gp8-lyrics-design.md), supporting [the umbrella design](../specs/2026-10-15-gp8-feature-parity-design.md). Canonical DTO bodies and semantics live in the subsystem spec; executors read both.

## Global Constraints

- Native projects remain schema version **2**, engine version **1.8.4**, immutable source plus finite commands. Old history retains its meaning.
- Use alphaTab **1.8.4**, fflate **0.8.3**, and the existing React/TypeScript and Rust/Tauri stack; no dependency changes.
- Root owns shared TypeScript/Rust DTOs and validators, engine/router, App/EditorPanel/ScoreView, model rebuilds, GP adapter integration, selection/export integration, Git, and desktop verification.
- Feature workers edit only assigned new modules, panels, tests, and authored fixtures. Do not edit installed alphaTab or first-delivery feature files.
- DTO indices are zero-based; measure labels are one-based. Validate complete payloads and destinations before mutation. Undo/redo uses deterministic history replay.
- Standard GPIF fields must be demonstrated by public readers/writers or authored GP8 fixtures; no invented extension elements, IDs, or private properties.
- Model retention, native replay, rendered notation, musical output, and target-runtime GP8 compatibility require separate evidence.
- Lyrics are per selected track, with at most five source lines. Hidden-source GP encoding and mixed/embedded-comment syntax compatibility remain open until authored GP8 fixtures establish them.

## Review Focus

1. Shorter/hidden/removed verses clear stale assignments, including a beat that became a rest — Task1.
2. Clone/rebuild, track/bar deletion, and first-staff/voice changes preserve source identity and offsets — Tasks2/4.
3. Imported raw source differs from reconstructed distributed text and remains untouched until Apply — Tasks2/3.
4. XML escaping, blank verse slots, reordered track IDs, and source/archive immutability preserve exact data — Task3.
5. Native/frontend schemas agree on line bounds, unknown fields, visibility, and atomic invalid input — Tasks1/4.
