## 2. Commands to bump consistently

Run in the checkout root on `develop` (or the release branch) after the tickets in section 5 are done. PowerShell:

```powershell
npm version 1.0.0 --no-git-tag-version          # package.json and package-lock.json together
(Get-Content src-tauri/tauri.conf.json -Raw) -replace '"version": "0\.2\.0"', '"version": "1.0.0"' | Set-Content -NoNewline src-tauri/tauri.conf.json
(Get-Content src-tauri/Cargo.toml -Raw) -replace '(?m)^version = "0\.2\.0"', 'version = "1.0.0"' | Set-Content -NoNewline src-tauri/Cargo.toml
cargo update --offline -p tabplayer --manifest-path src-tauri/Cargo.toml   # rewrites only the tabplayer entry in Cargo.lock
```

Then check that the change is exactly the five files and one `Cargo.lock` entry (`Cargo.lock` also holds unrelated third-party crates at 0.2.0, so a search for `0.2.0` there is not a valid check):

```powershell
git diff --stat
git grep -n '0\.2\.0' -- package.json src-tauri/Cargo.toml src-tauri/tauri.conf.json   # prints nothing
Select-String -Path src-tauri/Cargo.lock -Pattern 'name = "tabplayer"' -Context 0,1       # shows version = "1.0.0"
Select-String -Path package-lock.json -Pattern '"version"' -List | Select-Object -First 3   # the top entry and packages[""] say 1.0.0
npm run typecheck
npm test
cargo test --locked --workspace --manifest-path src-tauri/Cargo.toml
```

`Set-Content -NoNewline` keeps the file's line endings only if they were LF; check the diff for whole-file changes and use an editor if it shows any. The first command must print nothing; the other two must show `1.0.0` for the workspace entries only. Do not run the desktop app as part of the bump.

## 3. What CI produces

Workflow `.github/workflows/desktop.yml` ("Desktop tests and unsigned packages") runs on every push, pull request and manual run, on `windows-2022`, `macos-15` and `ubuntu-24.04`, with Rust 1.90.0.

- Each job runs the frontend and resource tests, the native tests and the plug-in host tests, then builds shipping packages with `--locked` and no `desktop-test` feature, signing identity, updater key or test server, and verifies the package contents offline.
- Bundles per system: Windows `msi` only (with the bundled audio and the offline WebView2 installer, NSIS fails, as the workflow comment says); macOS `app` and `dmg`; Linux `deb` and `appimage`.
- Artefacts: `verification-<os>-<sha>` (small resource reports, kept 7 days, always uploaded) and `unsigned-packages-<os>-<sha>` (the installers, kept 1 day, uploaded only when the workflow is started by hand with `upload_packages` ticked).
- **All packages are unsigned.** There is no code-signing, no notarisation and no updater key. Windows SmartScreen and macOS Gatekeeper will warn.
- CI does not create a GitHub release, a tag or a download page. Publishing is a manual step (see questions).

## 4. Release notes, draft

Draft for the owner to correct. Everything here is taken from `docs/validation/` and the parity tracker; where a claim is limited, the limit is stated next to it.

### TabPlayer 1.0.0

TabPlayer is a desktop tablature player and editor for guitar and bass. It runs offline.

**Open, save and keep your work**
- Open `.gp`, `.gpx`, `.gp5`, `.gp4` and `.gp3` Guitar Pro scores and your own `.tabplayer` projects; import MIDI files (formats 0 and 1, with quantization options) and ASCII tablature text. Several scores open in tabs.
- Power Tab (`.ptb`) and TablEdit (`.tef`) files open as experimental imports that list what they drop. The Power Tab import was tested only on synthetic files; the TablEdit import on 60 short test files.
- Crash recovery: timed recovery backups bring back your open documents after a crash, and the last session is restored on start.
- A library of folders, recent files, templates and examples.
- Export to Guitar Pro, MusicXML, MIDI, ASCII tab, PDF, and audio (WAV, MP3, FLAC, AIFF). An export tells you what a format cannot hold before it writes the file; round trips are not lossless.

**Read and edit**
- Edit notes, rhythm, techniques, chords, lyrics, repeats and tempo with undo and redo; select, cut, copy and paste ranges, also between scores.
- Score layouts (vertical and horizontal pages, grid, parchment and screen modes), tablature, standard notation, slash and numbered notation.
- Keyboard note entry (letter keys, duration, dot, triplet and rest keys), and a command palette with typed commands.
- 25 tuning presets, your own saved tunings, capo and instrument views (fretboard, keys, drums).

**Limits you should know about**
- MIDI note capture (play a chord on a MIDI keyboard or MIDI guitar to enter notes) has been tested only with simulated input. It has not been tried on real MIDI hardware.
- Exported Guitar Pro files have not been opened in Guitar Pro itself; that check (the export matrix, THE-61) is still to be done by the owner. Until then, treat exports to Guitar Pro as untested in the original application.
- Windows is the platform TabPlayer is accepted on. macOS and Linux packages are built and tested by CI, and have not been accepted on a real machine.
- The packages are unsigned: expect a warning from Windows SmartScreen or macOS Gatekeeper.
- There is no updater. This release has no update service; to update, install a newer version.
- Plug-in hosting (VST3) is packaged for Windows only: the CI build that includes the plug-in host runs on Windows, and the macOS and Linux packages do not carry it.
- Some labels are still English in Estonian and German (the Export window and the page layout panel, according to the tracker row W21).
- No physical printer test has been made; printing goes through PDF export.
- Not every Guitar Pro feature exists; the parity tracker (`docs/validation/2026-10-15-gp8-parity-progress.md`) lists what is complete, partial and open row by row.
