## Selected architecture and alternatives

Use a small versioned native catalog, immutable content-addressed personal-template payloads, one bounded native folder scan, and one disposable metadata worker. React presents these through one Library/Welcome surface outside the keyed document App. Every actual open returns the existing `DocumentIntake` and follows `buildDocument → workspace_add` or existing-document activation. Indexing never stages or activates a document.

A frontend localStorage catalog is smaller but loses native path identity, cross-process ownership, durable acknowledgment and scoped file access. A general database/media-library service adds dependencies and unrelated infrastructure. The selected native JSON catalog and per-root metadata files cover the requested local workflow, including atomic publication, with existing libraries.

For template history, compare two explicit representations. An undo floor in the current edit vector makes cursor/saved comparisons, redo and compact-save pruning depend on a second boundary everywhere, and allows baseline commands to masquerade as user undo history. A separate immutable baseline prefix makes the existing user-history cursor retain its meaning. Choose the latter, accepting a documented native project version migration. Exporting the template to GP would lose native sounds/settings/assets and is rejected.

## Project schema 3: exact template baseline

Canonical project and IPC `ProjectView` schema **3** add required `baselineEdits: EditCommand[]`; existing `edits` remains the user-history vector. `BaseDocument` and asset encodings are unchanged. All new native saves write schema 3. Strict schema 1/2 readers migrate to schema 3 with `baselineEdits=[]`; schema 1 also retains its existing empty-assets migration. Future versions and unknown fields still reject. Do not silently reinterpret a legacy edit vector as an immutable baseline.

Replay the ordered sequence `baselineEdits + applied edits` with one absolute index. Existing `added/<index>/<command>` track identities and sound/mix/engraving references must remain exactly stable when a source's applied edits become a template baseline. All settings replay, source mix/backing detection, preview, export, asset validation and pruning inspect the combined sequence where musically relevant. Undo/redo and dirty comparison inspect only user edits versus the exact saved user-edit vector.

`ProjectSession::fork_project(&self) -> Result<Project,String>` returns a new schema-3 project whose baseline is the source baseline plus the currently applied user edits, `edits=[]`, and assets reachable from that combined baseline. It excludes source redo-only and saved-other-branch commands/assets. It preserves every applied note, track, notation field, original byte, sound, effect, mix, backing configuration and referenced asset. Creating or using a template never changes the source session's cursor, saved comparison, path, revision, candidates or assets.

A newly instantiated template/example is clean, unsaved (`path=None`), stopped, with fresh document/activation/candidate identities, default repaired view, `cursor=0`, `saved=[]`, `canUndo=false`, `canRedo=false`. Its first user edit is independently undoable back to the exact template; the template content itself cannot be undone. Creating a template from another template concatenates prefixes without changing absolute replay indices. Save/reopen preserves this boundary. Explicitly distinguish clean unsaved template content from an empty disposable blank in recovery: a nonempty baseline must survive clean session restoration and Save/Discard decisions.

`ProjectCheckpoint` fields and recovery envelope version 1 can remain unchanged: the nested project is versioned. Native deserialization accepts and normalizes legacy nested projects before session reconstruction; schema-3 checkpoints preserve baseline plus all user-history/redo/saved-only assets. `saved_checkpoint` always retains the baseline, projects the saved user branch, and keeps assets needed by either. Digest verification remains over original file/checkpoint bytes before migration; a loaded schema-2 file retains its exact original save receipt until a successful schema-3 save. A newer project version is not readable by an older app; do not promise downgrade compatibility.

Native staged candidates gain a private purpose marker `OpenPath` or `Fork`. OpenPath retains W05 path/alias deduplication. Fork bypasses duplicate-open lookup and creates an entry with `imported_path=None`, even if `BaseDocument::File.filename` names a currently open source. Keep that filename/bytes/hash for source protection. Cancel/error consumes the marker alongside the candidate; recovery persists the explicit absence of an intake alias. Never change the canonical filename just to evade deduplication.

## Native catalog and persistence

Production data lives below `app_data_dir()/file-library-v1/`: `catalog.json`, `index-<rootId>.json`, `templates/<sha256>.tabplayer` and one held `library.lock`. IDs are nonempty opaque native identifiers, never user path fragments; only validated lowercase SHA-256 values form payload filenames. Root IDs used in index filenames are exactly 64 lowercase hexadecimal characters. A process-held `fs2` lock is acquired before catalog reads. Under both `desktop-test` and `TABPLAYER_DESKTOP_TEST=1`, derive an isolated library directory beneath the already-required absolute test session directory; production ignores test environment overrides.

`catalog.json` is strict `{format:"TabPlayerFileLibrary",version:1,revision,welcomeSeen,recents,roots,templates}`. Revision is a JS-safe nonnegative integer and increments only after a successful durable mutation. `welcomeSeen` defaults false only for an absent catalog. Records retain native paths, not frontend-resolved paths. Absent catalog means an empty catalog; corrupt/future/oversized catalog remains byte-identical and produces a factual Library unavailable issue, with ordinary picker/New/Save still usable. Do not auto-overwrite or automatically reset it.

Bounds: 100 unpinned recents, 64 pins, 16 configured roots, 128 personal templates, 512 MiB encoded per template, 4 GiB aggregate referenced personal-template payloads, 2 MiB catalog, 50,000 indexed files across roots and 32 MiB encoded aggregate index metadata. Reject an addition beyond a bound before changing prior data; report the limit and a useful action. Unpinned recent eviction alone uses deterministic oldest-last-opened order. Never evict pins, templates or roots silently.

Mutations accept `expectedRevision`; stale UI writes reject and refresh rather than overwriting another change. Serialize catalog mutations in one store mutex. Personal template creation writes/verifies a new immutable payload before atomically replacing the manifest that references it. Removal atomically retires references before deleting only unreferenced app-owned regular payload files. Interrupted writes leave the previous catalog authoritative; unreferenced payloads are never templates. Cleanup attempts all eligible owned files; unresolved cleanup debt blocks further payload creation, while a prior committed mutation remains acknowledged with a warning. Recognize only the pinned atomic-write-file temporary filename grammar for known app targets; preserve symlinks, directories, unknown files and near-matches. No broad recursive deletion. Preserve corrupt data for diagnosis without copying private content into the repository.

Catalog/index/template status and write errors are separate from music save/recovery status. A failed recent write cannot turn a successfully opened/saved score into a reported music failure. Keep the committed workspace result, show a Library history warning and allow Retry. Keep pending successful-open/save receipts in memory, deduplicated by native path with latest receipt per path and the same100-unpinned/64-pinned bound; Retry merges them into the next durable catalog mutation without duplicating entries. Under the existing store serialization, successful explicit Remove recent first commits removal, then retires all matching already-pending receipts for that native path using the same path identity comparison. Failed removal preserves both catalog and pending receipts. Retry/restart must not recreate an explicitly removed entry from those older receipts; a genuinely later successful open/save may add it again. Metadata enrichment only updates an existing recent and cannot itself recreate a removed entry. No tombstones or event ledger are needed. Report inability to retain additional history explicitly; never misreport music failure. Pin/template/configuration mutations are never silently queued as successful. Do not claim a recent/pin/template mutation succeeded until its catalog commit succeeds. No catalog fallback may resurrect a removed recent, template, pin or root.

## Recent files and acknowledgment

Record a recent only after a successful workspace add/activation or successful native save, not after a picker selection, staged read, cancelled dialog, failed canonical parse, rejected revision or failed write. Picker, recent, indexed-result and drop routes share this rule. Template/example forks enter recents only after their own successful native save; internal bundle/template paths are never recent user files.

Root captures a private intake receipt before candidate consumption and joins it to the successful workspace result. A native save uses its successful path/digest receipt. Update catalog I/O outside workspace/audio locks. Deduplicate with existing `path_identity`/`same_path` semantics, preserve an existing entry ID and pin, update last-opened time, and retain distinct copied files at different paths. Do not advertise hard-link identity or complete Unicode case folding beyond the current implementation.

Entries expose last-known title/artist plus filename/path and `availability:"available"|"missing"|"unreadable"|"unknown"`. Missing/unreadable entries remain visible and removable; a failed reopen reports the actual path error and never discards dirty work. Pinned entries sort before unpinned, with recency within each group; Pin/Unpin and Remove affect catalog only. Refresh rechecks existence off locks. A new open rereads the source; W05 same-path intake instead activates the intact already-open tab, even when its source moved or changed, and never silently reloads dirty music. Bounded metadata acknowledgments from the built document must match document ID, current revision and the intake/save receipt; stale callbacks cannot overwrite a newer entry. Filename fallback is honest while metadata is unavailable.

## Configured folder index and metadata search

Add folder uses the native plugin-dialog folder picker on a blocking worker; cancel makes no catalog change. Canonicalize the selected existing directory. Store roots with stable IDs and a configuration revision; scan recursively without following symlink directories/files, maximum depth 64. Deduplicate canonical paths across overlapping roots, retain which configured root authorizes each result, and never traverse app-owned library/recovery storage. Do not infer authorization from a string-prefix comparison.

Only the current supported intake suffixes participate: `.tabplayer`, `.gp`, `.gpx`, `.gp3`, `.gp4`, `.gp5`, `.xml`, `.musicxml`, `.mxl`, case-insensitive. Unsupported files do not appear as parsed scores. A scan is native-owned, cancellable and limited to one global active job, one file read and one metadata worker parse at a time. Starting a new scan retires the old job first. Check cancellation between directory entries and read chunks; dropping a blocking-task handle is not cancellation. The root ID/configuration revision/job ID must still match before accepting callbacks or publishing an index. Removing a root cancels its job and durably retires its index before acknowledgment; late callbacks cannot recreate it.

Native enumeration emits batches of at most 100 descriptors. IDs map to paths inside the active job; frontend requests contain job/file IDs, never arbitrary filesystem paths. Before returning source data, recheck canonical root membership and regular-file status, then compare size/modified metadata before/after the exact read and hash those bytes. Changed, inaccessible or outside-root entries are skipped with counted issues. A search result is a last-indexed observation; ordinary Open reruns native path admission and rereads/revalidates current content for a new tab, or activates the existing W05 same-path tab without silently reloading it.

Direct score input limit is 64 MiB; `.tabplayer` index input limit is 512 MiB encoded. Use a streaming JSON index projection to skip asset payload strings and unrelated music commands instead of `Project::validate`/full asset decode. It accepts strict known project versions 1/2/3 and emits only blank/file base metadata plus the seven relevant metadata operations in baseline-then-applied order. Limit encoded emitted metadata operations to 2 MiB per file and embedded original score to 64 MiB decoded. This projection is deliberately not canonical project validation or migration; malformed/oversized files remain listed with Metadata unavailable and their ordinary Open route.

The worker uses public alphaTab `ScoreLoader.loadScoreFromBytes` only to obtain file-base title, artist, album and ordered track names. A blank base yields authored title/artist, empty album and `['Guitar']`. Fold exactly `setScoreInfo`, `setScoreMetadata` (album), `setTrackInfo`, `addTrack`, `addPitchedTrack`, `addPercussionTrack`, `removeTrack`; validate referenced indices and relevant fields. Preserve empty replacement strings; only add-track uses `name || 'Instrument'`. Clipboard/advanced music edits do not change these four fields. This small read-only projection avoids canonical `engine.ts` refactoring and DOM/provenance-dependent full replay. Compare it against canonical `buildDocument` for all relevant commands and advanced imported histories. New commands that change indexed fields must extend this projection and its equivalence tests.

Worker admission sets `maxDecodingBufferSize=32 MiB`, rejects GPX `BCFZ` declared expansion above 64 MiB, and validates ZIP expansion before invoking the importer. Feed bounded compressed chunks through installed fflate streaming decompression; count actual emitted bytes per entry and across all entries, discarding admission output instead of retaining a complete archive. Stop admission immediately above **32 MiB actual output per entry**, **64 MiB actual aggregate output**, or **4096 entries**, and reject declared/output size mismatches. Header declarations alone do not establish these bounds. Never invoke alphaTab unless the entire admission pass completes within every limit; a breach terminates admission before alphaTab archive/model materialization. Unsupported ZIP64/unknown-size forms become explicit metadata-unavailable entries, not silent empty metadata. Retain the 64 MiB compressed-input limit and one-file concurrency; the 8-second per-file deadline and cancellation cover both admission and importer work, terminating/recreating the worker when needed because the importer has no abort API. These are input/expanded-output/concurrency/time bounds, not a strict model-heap guarantee. Worker output contains only bounded plain metadata, never score/model/project replacement state.

Metadata fields are title, artist, album and ordered track names; no inferred duration, tuning, note density, difficulty or measure count. Persist file identity/digest/stat and summary, never score bytes/backing. Maximum stored summary field is 4096 UTF-8 bytes and 256 track names; truncate only presentation/index fields with an explicit `metadataTruncated` indicator. Search lowercases Unicode text, splits whitespace, and requires every token to occur in filename/title/artist/album/track names. Support All folders or a configured folder, Title/Artist/Modified sorting, and pages of 100 rows; request sequence plus index revision retires stale search responses. Search cached metadata off audio/workspace locks, with no file parsing per keystroke.

A completed scan atomically publishes a replacement per-root index. Root configuration mutations and final index publication share one short native library-operation gate: recheck the current root/configuration revision under that gate, then publish. This gate never includes workspace/audio locks or worker parsing. Remove first invalidates/cancels the job, commits catalog retirement, then removes only that root's app-owned cache. If catalog removal fails, keep the previous index and root, with the scan cancelled; a fresh scan remains possible. Cancellation or root enumeration failure retains the prior committed index; progress clearly says the old index is still in use. Individual unreadable/oversized/parse-failed files are counted and retained as filename-only rows with a factual status. A successful refresh removes vanished index rows; recent entries remain separately retained. Root unavailability retains its prior index labeled unavailable. Limits and permission errors are visible; never claim a complete scan after truncation.

## Intake, drop and reveal contracts

Extract the existing `read_candidate` path intake into root-owned `intake.rs` without changing picker filters, same-path activation, original byte capture or exact native digest. Recent/indexed Open resolves a native descriptor ID and calls it; template/example Open stages a Fork. `WorkspaceController` adds one common `openSource` transition around its existing candidate `buildDocument`, commit and cancel-on-failure behavior. Dirty existing tabs remain untouched because W05 opens another tab; any action that actually closes/replaces a tab still uses existing Save/Discard/Cancel. Do not add duplicate prompts or silently replace the active score.

Use native Tauri window drag/drop, not HTML5 file-object parsing. One root listener captures OS paths into a short-lived native drop token (maximum 32 supported files, 30-second expiry), emits only `{dropToken,count}`, and stages one indexed item through the same intake route. Do not accept caller-supplied arbitrary paths. Whole-window feedback avoids physical/CSS DPI hit-testing errors. Process a drop sequentially in source order under one workspace transition; canonical duplicates activate the existing tab, valid files can succeed independently, and a visible result lists unsupported/failed/skipped items. Do not erase earlier successes or dirty tabs when another item fails. During startup recovery, shutdown, modal/export or another workspace operation reject the drop with a factual notice; do not defer stale intake invisibly. Retire token/listener/pending callbacks on shutdown. File association/open-at-launch remains W13.

`file_library_reveal {document:DocumentRevision}` resolves only that still-open document's native saved path; unsaved/fork documents disable the action. Canonicalize/recheck a real parent and report missing/unreadable targets; never fall back to an imported original's directory while labeling it the saved document. Windows uses UTF-16 PIDLs with `SHOpenFolderAndSelectItems`, balanced COM/PIDL cleanup; macOS uses `/usr/bin/open -R` with separate arguments; Linux uses `xdg-open` with the absolute parent directory. Label the action **Open containing folder**, so Linux does not imply file selection. No shell-composed command or new opener plugin. Handle spaces, Unicode, commas, extended/UNC paths and launcher failure. API success means the reveal request was accepted, not observed visibility; actual OS acceptance needs desktop evidence on each supported platform.

Protect internal factory/example/template/catalog/index paths from document Save/Save As, GP export, audio/PDF export and print destination writes through the root's common destination admission seam. Preserve existing `protect_source` and cross-document protection. Template names and descriptor IDs never become arbitrary write paths. Library mutations and reveal do not change music history/revision or audio owner; metadata scanning must remain usable during ordinary playback and must not seek/stop it.
