# Drum maps (THE-219) - validation, 2026-11-17

Branch `agy/the-219-drum-maps`. A drum track can carry a drum map: which key each of the 94 standard drum sounds is sent as to the track's hosted VST3 instrument (THE-218) and to its MIDI output port. This note records what was built, how each claim was checked, and what is not done. Only the repository's synthetic test plug-in and the desktop-test build's recording MIDI port have been used; no commercial instrument, no drum library and no hardware has been tried, and nobody has listened by ear. The numbers of the five library layouts are third-party notes that were never checked against a library (section "Preset data", below).

## What was built

- **Articulation id through the plan.** A drum note's standard articulation id travels in the playback plan on its note-on and note-off, where its key alone does not say which sound it is (a rim shot and a snare hit are both key 38). It is the id the note's own table entry carries when that is a standard id of the same piece and sound, else the first standard articulation of its shape; plain General MIDI hits and golpe knocks carry none, so such plans serialize as before. Both the TypeScript and the Rust plan checks refuse an id that is not a standard id.
- **Per-track map on the mix.** `ChannelMix.drumMap` is a preset id plus only the rows changed from it (`[id, key]`, key `null` for no sound). It is validated alike in TypeScript and Rust from one shared fixture (`tests/drum-map-protocol.json`). A General MIDI map with no changed rows is written as no field, a row equal to its preset's is dropped on write, an unknown preset plays as General MIDI plus its rows, and a backing track refuses a map. Every preset carries an integer `revision`.
- **Resolution.** The map is resolved off the audio thread into two 128-entry tables: by articulation id, and by key for a plain hit. A key that is itself a standard id and a General MIDI output follows that id's row, so a plain hit and the same sound named by its id reach the same key; every other key sounds itself.
- **Hosted instruments and MIDI out.** Hit and end are mapped through the same table, a silent row sends and holds nothing, and the held-note count is by the key actually sent. Instruments get the map where the mix is prepared, for the playback and the export way of attaching. MIDI out sends the mapped keys on channel 10 and keeps what is held, owed and struck again after a seek or a loop wrap by the key sent. A golpe knock never reads a map. The built-in kits ignore the map.
- **Held notes on a map change.** A map changed during playback is a mix change, with no new plan. The instrument keeps the keys the plan still holds under the new map and ends the rest, and strikes nothing again. MIDI out lets go of only the keys the new map no longer holds; it states nothing of the channel again and strikes nothing.
- **Editor.** Under a hosted instrument in the sound dialog and under a chosen MIDI port, one Drum map select (General MIDI and the layouts), a status line, how many keys the track changes and how many of its sounds have no key, a "Keys" section that lists the track's sounds or all 94 by piece with a key field, a Changed marker with reset per row, candidate keys where a layout has them, and Reset all. Each change is one `setTrackMix` edit that keeps the rest of the mix; the current value records nothing.
- **File import and export.** Export writes every one of the 94 sounds as resolved plus the layout it came from (`tabplayer-drum-map`, version 1). Import is checked whole (at most 16 KiB read from the opened handle, exact keys, a newer version told apart, known sounds once each, keys 0 to 127 or none, a plain name of at most 64 characters) and stored as the base layout, or General MIDI when this build lacks it, plus only the rows that differ, as one edit that records nothing when the track already plays that map. A refusal is shown in the panel in English, Estonian and German.
- **Presets.** Five layouts named after libraries the owner has, as compatibility labels (see "Preset data").

## Limits

1. **The numbers of the five library layouts are unverified third-party notes.** Nothing was run against EZdrummer 3, Superior Drummer 3 or any GetGood Drums library. The owner's own exported layouts (Drum map, Export) are the reference.
2. **Only the owner's three libraries have presets.** Other libraries have General MIDI or a hand-edited map.
3. **No audition button.** A single sound cannot be played from the editor: the hit path and a stopped-transport listening window are not built, so a key is checked by playing the score.
4. **Hi-hat openness is by distinct keys only.** No CC4 is sent. Chokes are plain keys: no aftertouch and no extra hit at the note's end. The row format `[id, key]` cannot carry these; it would need a new format version.
5. **A sound with no key in a map is silent** (`null` row), not played with its General MIDI key.
6. **A held note whose row moves is released and not struck again** on either output; the next hit uses the new key.
7. **MIDI out: a late note-off for a note that was never sent can end another strike of the same key early.** The guard that fixed this exists for hosted instruments only (`8ec1f29`); MIDI out has no such guard.
8. **Custom articulations** in a track's own table that match no standard sound cannot be mapped individually and play by their key. Plain hits on keys that are not standard ids cannot be remapped either; such a key sounds itself.
9. **Sound names in the editor are English in every language.**
10. **Maps live in the project.** There is no app-wide map library; the file import and export is the way to carry a map to another project.
11. **Exported MIDI and Guitar Pro files do not apply the map** (nothing in the export code reads it). Audio exports with an instrument do. The built-in kits ignore the map.
12. **Older TabPlayer builds refuse a project that carries a map.** `ChannelMix` rejects unknown fields; a project without a map is unchanged.
13. **A later correction to a preset changes how existing projects that use that preset sound.** That is by design: the project stores the preset id and only the changed rows. The preset's `revision` field records such changes; nothing yet tells a user that a project's preset has changed.
14. **Two drum tracks on one MIDI port share channel 10** and can cut each other's notes on the same key (unchanged by this work).
15. **The instrument is still not struck again after a seek** into a held note.
16. **Windows only for hosted instruments.** The desktop run is Windows-only, and the CI run for this branch (macOS and Linux included) has not happened.
17. **Estonian and German texts are unreviewed.**
18. **Nobody has listened by ear.** Everything here is keys and levels decoded from the test plug-in's signal and bytes at a test port. The test plug-in is a square wave; no real sample library was loaded.
19. **The live edit is observed through the plan generation and the peak meter only.** The plan generation counts prepared plans; the driver cannot see whether a renderer object was rebuilt, so "no renderer rebuild" rests on the Rust tests (`audio_plugin_instrument.rs`, `audio_midi_out.rs`), not on the desktop run. The live key is inferred from a louder peak (key 100 against 38), not decoded.
20. **The native file dialogs were driven with window messages**, which proves the app reads and writes the chosen path, not that the dialog looks right or that a person can use it.
21. **The desktop test build script needs a workaround in worktrees with linked resource folders.** `scripts/build-desktop-test.ps1` fails when `src-tauri/resources/library` is a junction (`prepare-library.mjs` refuses to write into it). This run built with a copy of the script outside the repository whose frontend step runs only the notices step, `tsc` and `vite build`. The script itself was not changed.
22. **The CI desktop job** timed out at 90 minutes during packaging on the last run with every test passed (the Windows native test step took 59 minutes); its limit is now 120 minutes, which has not been run.
23. **Not repeated here:** the full workspace Rust run and `npm test`.

### Octave convention

Every number used is a MIDI note number as the source prints it. No source used here gives only names, so no octave conversion was applied and there was no 12-semitone step to get wrong. Drumverter prints names under two conventions beside each number (kick 36 is C2 with C-1 = 0, and C1 with C-2 = 0); only its number column was used. The app's own note column calls 60 C4.

### Rule for filling rows

A key is used only when at least one source supports it for that sound. Where sources disagree, the best-supported key is the row and the others are its `candidates`, which the editor shows as one-click tries. A technique the library has no separate key for points at the piece's plain key only when a hit on the piece is clearly better than silence (a ride's middle, rim shot, side stick and half-open hi-hat on a snare or hi-hat). A choke with no mute or choke key is silent, because striking the cymbal again is the opposite of a choke. A library that names a muted hit ("Crash 2 (Mute)", "Ride (Mute)") has it used for the choke; that is the library's name for it, not a documented choke. Percussion a library does not have is silent. The six General MIDI toms (high, high-mid, low-mid, low, high floor and low floor) go to the library's toms from the highest to the highest, and the extra ones share the lowest rack tom (see below). The second ids of a sound (side stick 2, ride edge 2, ride middle 2, ride bell 2, ride choke 2, the tambourine and shaker variants, the two clash cymbals) follow their first.

### Rows nobody documents

No source says which key plays a half-open hi-hat in any of these libraries; the half-open rows are a choice among the open keys by name. No source covers the electric snare, the reverse cymbal (silent in all five) or the two clash cymbals (115 and 116), which follow the high crash key. ### Limits

- Nothing was checked against any library.
- Drumverter, Whack Studio, the Studio One list and the gist are third-party and may be wrong or describe a different edition of a library or a different kit; Whack Studio says itself that cymbal keys depend on the kit.
- Superior Drummer 3 and EZdrummer 3 can be remapped by their users and by the library's own presets, so a different layout may be in use on any machine.
- GetGood Drums layouts differ per pack and per mapping, and only the default mappings of the three packs above were read.
- The first-hand source for all of this is the library's own mapping view; exporting a map from it into this app's file format is the way to replace these rows.

### Drum-note remap toggle

Analogous to the guitar Tuning dialog's Keep fingering / Keep pitch choice, both **`DrumRemapDialog`** (`src/editor/DrumRemapDialog.tsx`) and **`DrumMapPanel`** (`src/audio/DrumMapPanel.tsx`) now offer an opt-in note-rewrite toggle (`Update drum notes for the new mapping` / `Update drum notes when switching layout`, default off):

- **Off (default):** Updates only `mix.drumMap` on the track (for hosted instruments, MIDI output, and MIDI export's `Apply drum maps` option), leaving the scored drum pieces unchanged.
- **On:** Re-interprets the track's drum notes from the track's previous `mix.drumMap` into the newly chosen mapping (`presetRemapForTrack(sounds, toMap, fromMap?)` in `src/editor/drum-remap.ts` + `remapPercussion`), so a track can be imported in one mapping, converted in place, and exported in another.
