# GP8 parity: MP3 audio export (F19)

Date: 2026-11-06. Branch `feature/f19-mp3-export` from `develop` at `1debe7a`. Linear THE-64 (shared with OGG, F20).

## What changed

- The Export dialog's File type offers **MP3 (compressed)** next to WAV, AIFF, FLAC and OGG Vorbis, for mixed audio and for stems.
  - MP3 hides bit depth, which does not apply to it.
  - A note says the file is lossy, at a constant 256 kbit/s, and that normalized peaks can go slightly past −1 dBFS after compression.
  - The file is saved as `.mp3`. Stems are written as `.mp3` files and recorded in the manifest with container `mp3`.
- `PcmWriter` (`src-tauri/src/export/wav.rs`) gains `AudioContainer::Mp3`, encoded by `src-tauri/src/export/mp3.rs`, a small wrapper over the LAME C API.
  - Encoding is joint stereo, constant 256 kbit/s, at LAME quality 2 (its recommended high quality). No ID3 tag is written.
  - LAME reserves the first frame. At the end, its information tag, which holds the length and the encoder delay and padding, is written over that frame, so players that read it play the exact length.
  - Samples must be finite and are clamped to ±1.
  - Normalization feeds MP3 through the same path as WAV, and cancelling still leaves any earlier file in place.
- Requests without a container, and existing `aiff`, `flac` and `ogg` requests, are unchanged. `"MP3"` in upper case is rejected, like the other names.
- **New dependency:** `mp3lame-sys` 0.1.11, pinned with its checksum in `Cargo.lock` (it adds `autotools` 0.2.7 as a build dependency on macOS and Linux).
  - It builds the LAME 3.100 release bundled in the crate (its MPEG decoder off): with `cc` on Windows, and with LAME's own `configure` through `autotools` on macOS and Linux. The library is linked statically.
  - Not chosen:
    - `mp3lame-sys` 0.2.0 bundles a "LAME 4.0" that matches no LAME release, and differs from 3.100 in 33 files of `libmp3lame`.
    - The higher-level `mp3lame-encoder` crate keeps its handle private, so it cannot fetch the information tag.
- **Licences:**
  - LAME is under the GNU Library General Public License, version 2 or later (`gain_analysis.c` under the LGPL 2.1 or later); the crate is LGPL-3.0.
  - TabPlayer is MIT-licensed open source (`LICENSE`, committed on `develop` as `1debe7a`), so the app can be rebuilt against a modified LAME, as the LGPL asks of statically linked programs.
  - `THIRD_PARTY_NOTICES.md` names LAME, its copyright holders and the crate, and points to the published crate as the corresponding source.
  - `scripts/copy-notices.mjs` now also copies `COPYING` and `LICENSE` from the crate's `lame-3.100` folder into the package inventory.

## Evidence

- **Native unit tests:** `export::` in `--lib`, 50 passed.
  - **Round trip** at 44.1 and 48 kHz:
    - Input is 10 s of two-channel tones, fed in alternating 300 and 512 frame blocks.
    - The file starts with an MPEG-1 Layer III frame, its first frame carries the `Info` and `LAME` tag, and it is about 256 kbit/s in size.
    - Symphonia decodes it independently to exactly the input's frame count, with over 30 dB SNR on each channel against the input.
  - **Determinism:** a second encode of the same blocks is byte-identical.
  - **Empty, invalid and clipping input:**
    - An empty export succeeds.
    - NaN and infinite samples are errors.
    - Input at three times full scale is clamped, and decodes with a peak between 0.9 and 1.3.
  - **Stems:** each MP3 stem decodes to 48 000 frames, a 440 Hz stem carries the tone, and a silent stem stays silent.
  - **Requests and cancellation:** serde accepts `mp3` and refuses `MP3`, and a cancelled MP3 export leaves the earlier file in place.
- **Frontend:** `src/export/mp3-export.test.tsx` checks that:
  - the dialog names the file `.mp3`, hides bit depth and shows the note;
  - it sends `container:'mp3'`, with and without normalization;
  - switching back to WAV brings bit depth back and sends the old request shape;
  - stems export as MP3.
  `src/export/aiff-export.test.tsx` checks the new order of file types.
- **Desktop** (`tests/desktop/parity-mp3-export.mjs`, Windows desktop-test build):
  - The driver exports a sustained E2, B2 and E3 on a steel-string guitar through the Export dialog, as MP3 and as 24-bit WAV, at both rates.
  - Symphonia decoded the MP3 files through the `decode_audio` example:

  | Export | Frames (MP3 = WAV) | SNR against WAV | MP3 bytes | WAV bytes |
  |---|---|---|---|---|
  | 44.1 kHz | 264 600 | 61.8 dB | 193 932 | 1 587 644 |
  | 48 kHz | 288 000 | 64.4 dB | 193 536 | 1 728 044 |

  - Stems at 48 kHz wrote `001-Guitar.mp3` and `002-Mix.mp3`, with manifest container `mp3`. Both decode at 48 kHz in stereo.
- `cargo fmt --check` and `npm run typecheck` are clean.
- The parity tracker's counts were recomputed from its rows; they now include F20 (OGG), which the OGG change had left uncounted.
- In this worktree, `src/export` and `src/i18n` Vitest give 547 passed and 8 failed. All 8 failures are in `midi.test.ts` and `musicxml.test.ts`, which read `.analysis/compatibility` fixtures that worktrees do not have.

## Review

A fresh-context adversarial review of the dependency, the FFI and the notices found no reachable memory-safety bug. Fixed after it:

- `Mp3Encoder::encode` now refuses non-finite samples itself, not only through `PcmWriter`, since LAME would index its tables with a NaN.
- Encoder setup holds a lock, because `lame_init_params` rewrites LAME's shared lookup tables.
- The empty-export test checks the MPEG header and the information tag, and that the decoder finds no audio frames.
- The notice names the GNU *Library* GPL version 2 or later, and no longer claims the bundled source is byte-identical upstream: the crate's `include/libmp3lame.sym` lacks `lame_init_old`, a common distribution fix in a file a static build does not use.

Open from the review:

- The GitHub repository is private. The MIT source must be public, at the release commit, before any build that includes MP3 export is distributed, as the LGPL relinking route depends on it.
- The crate is LGPL-3.0, which asks for the GNU GPL 3.0 text to be shipped beside it; it is not yet in `legal/`.
- The bundled tree is not diffed against the official `lame-3.100.tar.gz`.
- CI builds only arm64 macOS, so the x86_64 macOS LAME build path is unexercised.

## Limits

- Fixed constant 256 kbit/s, with no bitrate, VBR or quality choice.
- No title or artist tags.
- Not listened to.
- Built and run on Windows only; the macOS and Linux `autotools` build of LAME is untested here and is left to CI.
- The bundled LAME source was not byte-compared with the official 3.100 tarball. It reports version 3.100 as a release, its tree is identical in mp3lame-sys 0.1.9 and 0.1.11, and `Cargo.lock` pins the crate by checksum.
- Players that ignore the LAME tag play LAME's encoder delay (about 1 100 samples) and end padding as silence.
