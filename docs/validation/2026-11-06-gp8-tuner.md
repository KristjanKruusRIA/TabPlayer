# GP8 parity: chromatic and polyphonic tuner (U18)

**Date:** 2026-11-06.
**Branch:** `feature/u18-tuner`, from `develop` at `5ae0bd0`.
**Linear:** THE-69. It also covers line-in monitoring (A28 and A29), which is not done here.

## What changed

### Where it is

The Practice tools now have a **Tuner** section (`src/audio/TunerPanel.tsx`). It sits outside the practice controls that are disabled while the editor is busy, so listening can always be stopped. It offers:

- **Input:** the system's audio inputs, with the default marked. The list is read again each time the section opens, so a newly plugged-in interface appears. Changing the input while listening moves capture to the new input.
- **Mode:**
  - **Chromatic:** the nearest note, its octave and how many cents it is off, on a ±50-cent meter. Within 3 cents it reads "In tune".
  - **All strings of this track:** every open string of the selected staff, each with its cents or "Not heard". Strum the open strings and every one is checked at once. A line under the table suggests finishing the higher strings in chromatic mode (see Limits). For a percussion track the panel uses chromatic mode.
- **Reference A4:** 415 to 466 Hz, default 440. The note names and string targets follow it.
- **Start / Stop listening.** Listening also stops when the app closes, when the panel unmounts, and when the Tuner section or any section around it (such as the Practice popover) is collapsed. A collapse that happens while a start is still on its way stops that capture as soon as it arrives.
- **Feedback:**
  - After 1 s of continuous input at or below −90 dBFS, the panel says nothing is heard from the input. This is what a refused microphone permission produces.
  - The reason is shown when the device stops. A failed read is reported and cleared by the next good one.
  - Screen readers hear only the note and whether it is in tune, not every cents update.

All text is in English, Estonian and German. Cents are formatted for the interface language.

### Native capture and detection (`src-tauri/src/tuner/`)

- **Commands:**
  - `tuner_inputs` lists the inputs.
  - `tuner_start(inputId)` returns a session number.
  - `tuner_stop(session)` stops only that session, or any session when none is given, so a stale stop cannot end a newer capture.
  - `tuner_read(strings)` returns the level, the chromatic pitch and one measurement per target string. Only the first 12 targets are used, and an invalid target reads as not heard.
- **Capture:**
  - A cpal input stream runs on its own thread, using the device's default configuration. Another configuration is chosen only for DSD formats or a rate outside the supported range, and it keeps the channel count.
  - The audio callback picks the loudest channel of each block, with 6 dB hysteresis, so a guitar on one input of a multi-input interface is not diluted. It pushes into a lock-free ring buffer and drops samples when the buffer is full. It does not allocate, lock or block.
- **Analysis:**
  - A worker thread analyses the latest samples about every 50 ms. Input above 48 kHz is first decimated with a windowed-sinc filter to near 46 kHz: standard rates land at 44.1 or 48 kHz, others between about 34.5 and 69 kHz. The frontend polls every 100 ms.
  - **Chromatic detection** uses YIN from 30 to 1500 Hz, with a level gate at about −50 dBFS and a clarity gate. It runs only when no string targets are given.
  - **Polyphonic detection** uses a Hann-windowed FFT. For each target string it finds the strongest peak within ±50 cents, refines it, and reports it only when it rises clearly above the local floor and is not explained as a harmonic (3rd to 8th) of a lower sounding string. Octaves are never rejected as harmonics, so a string an octave above another is still heard. A string that was heard is held for 1 s, so a decaying strum does not flicker.
- **Stopping:** stop waits in 10 ms slices and gives up on a capture thread after about 0.5 s, so quitting is never blocked for long. A start that a newer start or stop overtakes gives up.
- **macOS:** `src-tauri/Info.plist` adds the microphone usage text that macOS requires before it allows input.
- **Desktop test build only:** a synthesized "Test tone" input, set by `TABPLAYER_TUNER_TEST_TONE`, so the whole path can be checked without a microphone. It needs the `desktop-test` feature and `TABPLAYER_DESKTOP_TEST=1`.

## Evidence

- **Native tests** (`cargo test --lib tuner`, 63 passed):
  - **Chromatic:**
    - Sines and harmonic-rich tones from 41.2 to 1000 Hz, at 44.1 and 48 kHz, each within ±1 cent.
    - A tone whose second harmonic is stronger than its fundamental gives no octave error.
    - Silence, white noise and a quiet tone below the gate give no pitch.
  - **Polyphonic:**
    - A full E2 A2 D3 G3 B3 E4 chord with strings detuned by −20 and +12 cents, each within ±3 cents.
    - Seeded random phases (50 sets): at equal level every string is heard in at least 43 of 50 sets and, with every string exactly in tune, every reading is within ±3 cents in at least 47 of 50.
    - With the steep and flat partial profiles, a lone E2 or A2 never lights up B3 or E4.
    - Drop D and DADGAD, which have strings an octave apart, are heard at any phase, and every lone string reports only itself.
    - A harmonic of a note that is not a target is not taken for a string.
    - **A detuned treble string beside bass harmonics** (`a_detuned_treble_string_beside_bass_harmonics_reads_as_a_blend`): B3 or E4 played 4 or 8 cents off against in-tune bass strings, over 50 random phase sets, with steep and flat partial profiles, at equal level and 6 dB down.
      - **8 cents off:** never read as in tune, and the test asserts this. The worst error was 3.4 cents at equal level with steep partials, 7.7 cents at 6 dB down, and 18.1 cents for E4 6 dB down with flat partials, which was heard in only 32 to 35 of 50.
      - **4 cents off:** read as in tune in up to 29 of 50 sets. A flat string reads in tune more often (10 to 29 of 50) than a sharp one (0 to 13 of 50).
    - A missing string reports nothing, and so do silence, noise and a note outside the search range.
    - The FFT matches a direct transform.
  - **Sample rates:** at high rates such as 96 and 192 kHz, YIN stays within one cent after decimation, and analysis at 192 kHz stays cheap. The decimation filter passes the band and blocks aliases, and chunked input matches a single call. At 8 kHz, low and high notes are still found.
  - **Capture:**
    - Loudest-channel selection and its hysteresis, and integer conversion.
    - Dropping when the ring is full, and the stream-error policy.
    - The test-tone path through ring, worker and reading.
    - Sessions: a stale stop leaves a newer capture running, and a stale thread cannot change the current state.
    - A failed start or restart, a hung start that times out without blocking stop, a stalled input, and a panicking capture thread.
    - A restart never reads as stopped and keeps the last level.
- **Frontend tests** (`src/audio/TunerPanel.test.tsx`, 14 passed):
  - Note names and cents against a chosen reference.
  - The chosen input is used, and the note and cents are shown.
  - "In tune" within 3 cents, and the screen-reader status reads only the note.
  - All strings at once against a 442 Hz reference, including an unheard string.
  - No string mode for a track without strings, a bad reference is refused, and start failures are reported.
  - A stopped device is reported.
  - Switching input keeps listening, even when a read during the restart looks stopped.
  - Unmounting during a pending start stops that capture once it arrives.
  - Collapsing the Tuner section stops listening, and so does collapsing a section around it.
  - The silence hint waits 1 s, and a failed read's alert clears on the next good read.
  - A start that failed after a collapse does not cancel the next Start.
  - The input list is read again on each open and keeps a choice that is still there.
  - A track without strings falls back to chromatic mode, and strings mode shows the hint.
- **Desktop** (`tests/desktop/parity-tuner.mjs`, Windows desktop-test build): the test input played A2 nine cents sharp (110.573 Hz).
  - **Native:** the chromatic reading was 9.00 cents. With all six standard targets, only the A string was heard, at 110.574 Hz. The other five, including high E (where the tone's third harmonic falls), were not heard.
  - **Panel, chromatic:** showed `A2 +9.0 cents`, and the status for screen readers read `A2`.
  - **Panel, all strings:** showed A2 at +9.0 cents and the five other strings as not heard.
  - **Collapse:** closing the toolbar's Practice popover stopped native capture (`tuner_read` reported not running), and Start and Stop worked again after reopening it.
  - Escape pressed inside the popover does not close it, because the tuner is rendered into the popover through a React portal, and React routes the key past the popover's own handler. This affects every practice control and predates this change; the driver closes the popover from its button.
  - No alert or page error. Screenshot: `.analysis/parity/native-tuner.png`, not committed.
- **Suites:**
  - `cargo fmt --check` is clean.
  - `cargo check` is warning-free with and without `desktop-test`.
  - `npm run typecheck` passes.
  - The tuner panel, editor panel and i18n Vitest files pass (83 tests).

## Review

A fresh-context, read-only adversarial reviewer (Opus) reviewed the slice in four rounds.

- **Round 1, not approved:**
  - A changed input left the old one open.
  - Bass harmonics were taken for treble strings.
  - An unmount during a start leaked the capture.
  - The worker's receive was unbounded, and YIN cost too much at high rates.
  - Channels were averaged.
  - Listening went on while the section was collapsed.
- **Round 2, not approved:**
  - A circular fall-off estimate dropped octave strings, and E2 was counted twice against E4.
  - The preferred configuration changed macOS device rates.
  - Collapsing the Practice popover around the tuner did not stop it.
  - High notes lost accuracy after decimation.
  - The silence hint flashed on every start.
  - A stale stop could end a newer capture.
  - Quitting could block for about 7 s.
- **Round 3, not approved:**
  - A native English notice was shown in every language.
  - Accuracy was measured only with every string in tune.
  - A failed start left a stop request that cancelled the next Start.
  - The input list never refreshed.
  - Strings mode on a percussion track showed an empty table.
  - Held strings came back after a mode switch.
  - A read failure's alert stayed up.
  - The real popover collapse was untested.
- **Round 4: approved.** Its two optional test points were also taken: the blend test now requires each string to be heard, and the read-failure test checks that the alert appears before it clears.

All findings were fixed, and the evidence above is from after the fixes. Escape inside the Practice popover was confirmed as an older issue, outside this change.

## Limits

- **Synthetic evidence only.** Results come from generated tones and the desktop-test "Test tone" input. No real guitar, bass, microphone or interface was measured, and there was no listening test.
- **Platforms.** Only Windows was driven. Not verified:
  - macOS and Linux capture, and their microphone permission prompts.
  - Tauri's `Info.plist` merge, and the `com.apple.security.device.audio-input` entitlement a signed, hardened macOS build will need.
  - On macOS, the fallback configuration (used only when the default is unusable) can change the device's sample rate for every app.
- **Start and stop timing.** Start gives up after 5 s, so a slow permission prompt may need a second Start. Stop leaves a stuck driver thread to finish by itself after about 0.5 s.
- **Chromatic mode** covers 30 to 1500 Hz above about −50 dBFS, within 1 cent on synthetic tones at 8 to 192 kHz. There is no needle smoothing or strobe display like GP8's; the reading updates ten times a second.
- **Strings mode basics.**
  - It searches ±50 cents around each target; a string further off reads "Not heard".
  - Only the first 12 strings are used.
  - A string that stops sounding keeps showing for about 1 s.
  - The first reading after a switch to strings mode shows no strings; the panel's next poll, about 100 ms later, is correct.
- **Shared partials.** Higher strings share partials with lower ones: B3 and E4 with E2 and A2 in standard tuning, and octave strings in Drop D, DADGAD, open tunings and 12-string.
  - **Heard rate:** at equal level every string is heard in at least 43 of 50 phase sets. With the treble 6 dB down, E4 is heard in only 21 of 50, so a string can read "Not heard" for a while; the 1 s hold covers some of this.
  - **Accuracy:** a detuned string's reading blends with the neighbouring harmonic. A string 4 cents off can read as in tune (up to 29 of 50 sets). A string 8 cents off never did, but its reading can be up to 18 cents wrong. The panel says to finish the higher strings in chromatic mode.
- **Lone strings.** The result that a lone string lights up only its own row holds for the steep and flat partial profiles tested. A low string with unusually strong upper partials, or a microphone that rolls off the fundamental, could light up the B3 and E4 rows.
- **Input handling.**
  - The loudest of the first 64 channels is followed, with 6 dB hysteresis, so it can follow hum or another source on a multi-input interface.
  - Rates of 8 to 768 kHz are accepted and decimated above 48 kHz. DSD is refused.
  - An input unplugged while listening stays listed until the section is reopened.
- **Microphone use.** The input is open only while listening. It closes on Stop, when the Tuner section or the Practice popover closes, when the panel unmounts and when the app exits, but not when the window is minimised.
- **Escape** inside the Practice popover does not close it. This affects every practice control and predates this change.
- **Error details.** Native error details are in English inside the localized "stopped" and "could not listen" messages.
- **Line-in monitoring** (A28, A29) is not part of this change.
