# GP8 parity E19: direct symbol editing and context menus (2026-10-31)

GP8 row E19: activate a displayed symbol and edit its existing value. Notes already select the inspector; this adds the title, tempo marks, chord names and clefs on the rendered score.

## Behavior
- **Double-click edits in place.** On the rendered score, double-clicking the title, a tempo mark (the `= 96` text, or its label), a chord name above a beat, or a clef opens a small editor beside it. Title, tempo and chord name are a one-line field (Enter applies, Escape cancels, the field is selected on open); a clef opens the five clef choices with the current one checked. Nothing else on the score reacts, and a click that is not on one of these symbols behaves as before.
- **Right-click opens the actions that fit.** Title: Edit title. Tempo: Edit tempo, and Remove tempo change when the mark is not the initial tempo. Chord: Edit chord name, Open chord editor (the existing harmony dialog on that beat), Remove chord. Clef: the clef choices. A menu has arrow, Home and End keys; Escape closes it.
- **Keyboard.** Shift+F10 or the Menu key, with the score focused, opens a menu of every symbol at the edit target: the title, each tempo mark of that measure (the initial tempo when the measure has none), the beat's chord with all three of its actions, and the clef of that staff. It opens beside the edit-target marker.
- **One edit per gesture, from existing edits only.** Title: `setScoreInfo`. Initial tempo: `setScoreInfo`; any other tempo mark, and removing one: `setMeasureSettings`. Chord name: `setHarmonyChord` (a manual name; the diagram and flags are kept). Remove chord: `setHarmonyChord` with no chord. Clef: `setBarNotation` for that measure and staff. No edit type was added, so old projects and edit logs replay unchanged, and Undo takes back one gesture.
- **Nothing recorded for no change.** Typing the current value, or choosing the current clef, closes the editor without an edit. A title or chord name with stray spaces counts as unchanged when typed back.
- **Refusals say why and keep what was typed.** A tempo outside 1 to 999 BPM, an empty or over-long chord name or one with control characters is explained under the field. A rename that `setScoreInfo` would turn into a different opening tempo (a labelled, gradual or hidden opening mark, or none at the start of the measure) is refused, as is rewriting a measure that holds a hidden or between-beats tempo mark, and renaming a chord that has no diagram for the staff. The editor waits for the edit to land: if the document refuses it, the editor stays with its text and says "The change was not applied."
- **Locked documents.** A finalized or password-locked score opens a menu instead of an editor: its message says why, every action is `aria-disabled` and none runs. The app's own handler refuses a stale edit as well.
- **Busy.** The editor still opens; Apply and the menu actions that record are `aria-disabled` through `busyGuard` (never `disabled`), the field keeps focus, and a status line says to wait. Opening another editor or going elsewhere is never blocked.
- **Focus.** The popover takes focus when it opens; Escape, Apply and a landed menu action return it to what had it before (the score). Clicking or tabbing elsewhere closes it without stealing focus back, and a changed score closes it and puts focus back on the score if it had been inside. Keys typed in it never reach the score's shortcuts (Escape no longer clears the selection).
- **Text.** All new strings are in `src/i18n` (`symbol.*`, 37 keys) in en, et and de; the lock message is the app's existing one.

## Review
A fresh-context Opus reviewer read the diff cold and found one High, five Medium and several Low points. Fixed and covered by tests: a title rename could rebuild a labelled, gradual or hidden opening tempo (now refused); editing or removing a tempo mark could reveal a hidden one in the measure (now refused); renaming a name-only chord failed with an unrelated message (now explained); a refused edit closed the editor and lost the text (it now waits and keeps it); the keyboard menu offered only the first action of each symbol and only the first tempo mark (now all of them); the native context menu could open over ours (prevented inside the menus, not in the text field); a changed score dropped focus to the page; trailing spaces defeated "unchanged". The Sound view no longer receives symbol editing. These fixes were not reviewed again. Not changed: see Limits.

## Limits
- **Desktop driver not run.** `tests/desktop/parity-symbol-editing.mjs` is written to the pattern of `parity-command-palette.mjs` and passes `node --check`, but no desktop-test build of this branch was made or launched (the driver attaches to `.analysis/desktop-smoke/tabplayer.exe`, which belongs to another build, and the worktree has no `.analysis`). Its selectors and the Gp7 fixture's tempo, chord and title round trip are unverified. Nothing here was exercised in WebView2; the browser run above was Chromium. The Menu key (as opposed to Shift+F10) was not pressed in a real browser; its native `contextmenu` event timing is handled but unobserved.
- **Text decides what a symbol is.** alphaTab reports no bounds for these symbols, so a click is resolved from the clicked `<text>` characters and the bounds of the measure under it. Beat text or a lyric spelled exactly like a chord name in a measure that has that chord opens the chord; an artist line equal to the title opens the title. A title is only found when it is non-empty (add one from the keyboard menu or the inspector). A mark that overhangs into the next measure is attributed to that measure. The chord diagram heading above the first system is not a hit target.
- **Clef is per measure.** `setBarNotation` changes one measure of one staff, so the next measure shows its own clef again. The menu names the measure; changing a whole staff is not offered because it would be many edits.
- **Refused cases stay refused.** A measure with a tempo mark between beats, with a label or hidden is edited from the inspector's Measure panel, which rebuilds it as it can; the opening-tempo rename guard means a score with a labelled opening mark is renamed there too (the inspector shares the same rebuild).
- **No automated test of the page-layout hit path.** The `unmapScreenPoint` branch for paper layouts was checked by hand in the browser page, once; the jsdom tests use the continuous layout's bounds.
- A lock message is shown in English because it is the app's existing constant.
- Not run: the full `vitest` suite or Rust tests (no Rust changed). Fixture tests that read `.analysis/compatibility` fail here with ENOENT as expected for a worktree and were not part of the runs above.
