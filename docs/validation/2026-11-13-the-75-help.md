# THE-75 (W21): fuller help with search, in en, et and de (2026-11-13)

Branch `agy/the-75-help`, from `develop` (`126a1c0`). This is the help half of THE-75. The update half is not built: there is no update service, signing key or signed artefact (see Limits). Result: **partial**.

## What was added

- **Coverage.** The viewer had 8 topics of 3 to 7 short paragraphs. It now has 14 topics and 49 sections, written from the code and from the validation notes of the features. New topics: Score display and zoom, Selection and clipboard, Instrument views, Engraving and page layout, Exporting, Command palette. The files topic is now Opening, saving and importing, and covers ASCII, MIDI, batch convert, saving and recovery. Playback now covers loops, speed, practice settings, backing audio, mixing, the tuner and Line-In. Tracks covers tunings, the amp chain, NAM captures, cabinet responses, interpretation and MIDI output. Editing covers note entry, the voice, track, bar and technique keys, and both palettes.
- **Corrections to the old text.** It said the playback controls are "in a bar along the bottom"; they are in the toolbar (`Transport` renders inside `.gp-toolbar`). The file-types paragraph named only Guitar Pro and MusicXML; Open also accepts Power Tab (.ptb) and TablEdit (.tef), and Export offers SVG, PNG, Print and Guitar Pro 5.
- **Search.** A search field above the topic list. See How search works.
- **Translation.** All help text is in `src/i18n/help-en.ts`, `help-et.ts` and `help-de.ts`, spread into the catalogs. The old `help.topic.*` keys were removed and rewritten (`help.topic.editing.p3`, `help.topic.shortcuts.practice` and `help.topic.shortcuts.tie` keep their names because tests pin them). A control name is never typed in the help: a text writes `{@menu.file}` and the viewer replaces it with that key's text in the current language, so the name in the help equals the name in the interface. Whole shortcut sentences that the Help menu already shows (`help.shortcut_*`) are reused the same way, so the two cannot disagree.
- **Context help.** F1 now opens a section as well as a topic. `helpContexts` maps 24 selectors; new ones are the tuner, Line-In, practice settings, backing, instrument view, edition palette, the Track tab's four sections, the Song tab's notation section, the Selection tab, the loop and speed controls and the display controls.
- **Source-literal guard.** `src/help/HelpDialog.tsx` is added to `sweepFiles`.

## How search works

- The query is folded: lower case, accents removed (NFD, combining marks dropped), ß as ss. The text of every section (heading and paragraphs, after the labels are filled in for the current language) is folded the same way. So `ruckgangig` finds "Rückgängig", `vota tagasi` finds "Võta tagasi".
- A query needs at least two characters. Every word of it must appear in the section, as a substring, so German and Estonian compounds and inflected forms match (`passag`). A word in the heading counts ten times a word in the text; ties keep reading order. At most 40 results.
- Each result is a button showing the topic, the section heading and a short excerpt around the first match, with the match in `<mark>` (bold and underlined, so it does not rely on colour). With a heading-only match the excerpt is the start of the section.
- While a search is on, the topic list shows only topics with a match, and the text area is replaced by the results; no match shows "No help topics match “…”".
- Keys: the field does not take the first focus (the current topic still does, as before). Enter opens the first result, Down moves into the results (Up/Down move between them, Up from the first returns to the field). Opening a result switches the topic, clears the search, scrolls to the section and focuses its heading. Escape clears the search and keeps focus in the field; Escape again closes the dialog. The Escape handler is on `window` in the capture phase, so it runs before the dialog's own handler on `document`.
- Announcement: one `aria-live="polite"` paragraph holds "One result.", "n results." or the no-match message. It has no `role`, because the existing About test needs exactly one `role="status"` in the dialog.
- Limits: it matches the current language only (an English word does not find Estonian text); it does not rank by how close words are or understand synonyms; it searches help text, not the app.

## Limits

- **Not run in the desktop app.** `tests/desktop/parity-help.mjs` was read, not run. From reading it should still pass: it opens F1 from the score and expects the dialog "TabPlayer help", the button "Editing the score" with `aria-current` and text containing "command palette"; "Getting started" with nothing focused; the About topic, its "Check for updates" button and status; the Help menu "About and updates". All of these names, the focus return and the status text are unchanged. F1 from the score maps to the topic only, so the flow is the same.
- **Estonian and German were not reviewed by a native speaker.** Terms come from the catalog through the label references; the sentences around them are mine. Estonian puts control names in „…“ because the names are in the nominative.
- **F1 inside a dialog is unchanged.** It still does nothing while another dialog is open (a review finding on 2026-10-23 asked for this, since Escape would close both). So the Export, MIDI import, ASCII import and Batch convert dialogs have no context help; the Help menu and the palette open help.
- **No updater.** "Check for updates" stays as it was: it says this build has no update service. The updater needs the Tauri updater plugin, an update endpoint, a public key in `tauri.conf.json` and signed artefacts from CI; it is a separate ticket.
- The help describes this branch; features on other branches are not in it.
