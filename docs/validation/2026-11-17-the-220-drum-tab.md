# THE-220: drum tablature

Date: 2026-11-17. Branch `agy/the-220-drum-tab`, cut from `develop`. This note records what the feature does, what the three adversarial
reviews found and what was done about each finding, and what has not been run.

## What it does

alphaTab 1.8.4 cannot draw percussion as tab. For a track of one percussion staff whose engraving profile is `tablature` or `standardTab`,
`projectEngraving` rewrites the display copy's JSON (never the source score): the percussion staff becomes, or is joined by, a six-line tab
staff whose "fret" is the written standard articulation id (36 kick, 38 snare, 42 closed hi-hat, 91 rim shot, 92 half-open hi-hat, 93 ride
edge, chokes 94-98), taken with the function the drum map uses; the track's drum map is ignored. Six lines, top to bottom: crashes, china,
splash, reverse and clash cymbals; ride, bells and other metal or percussion; the hi-hat family; toms; the snare family; kicks. A hit whose
line is taken by another at the same moment moves to the nearest free line, upward first. At most six hits at one moment are shown; the rest
are left off the tab (counted in the inspector) and stay in the score, playback, MIDI and Guitar Pro export.

The inspector's TAB and notation toggles on a drum track write the track's engraving profile (`source`/`standard`, `tablature`, `standardTab`),
one `setEngraving` edit per gesture, nothing for the current value, and the last notation that is on stays focusable and inert. No new Rust or
project-schema field. Old projects whose logs hold `setStaffSettings` edits with `showTab` on a drum staff still replay (validateStaff is
unchanged); they changed nothing then and change nothing now.

## Behaviour changes to know about

- A project that already holds the profile `standardTab` on a drum track used to draw standard notation only; it now draws drum tab beside it,
  on screen and in the PDF under the page profile "Document notation". The page profile "Tab" now gives drum tab for a drum track whose own
  profile is `standard`, where it used to fail.
- An older TabPlayer build refuses to open a project in which `tablature` was ever set on a drum track ("Tablature requires tuned nonpercussion
  staves"), because replay walks the whole log. Only internal `develop` builds have engraving profiles, so no released build is affected.

## Limits, stated plainly

- Numbers are the written sound numbers, not Guitar Pro's per-note drum-tab lines: alphaTab 1.8.4's importers drop that line, so a fixed rule
  decides the line. alphaTab 1.9 draws drum tab natively; this work is meant to be replaced by it.
- In standard + tablature the second staff is, for alphaTab, a tab-only staff. It also draws its own time signature, its rests and the rhythm
  (stems and beams) under the percussion staff, as a tab-only guitar track would; that cannot be turned off from the JSON. The marks that alphaTab
  hands to a staff with no score renderer (dynamics, fermatas, volta brackets, directions, triplet feel) are left off it by a guard in
  `src/engraving/drum-tab-guard.ts`, and its tremolo picking and fades are dropped in the JSON, so each is drawn once.
- Only ties between two hits written alike (same number on the same line) are drawn on the tab. Dead notes, staccato, palm mute and the like
  record undoable edits on a drum hit that the tab does not show; accents and tremolo rolls are not drawn in tab only.
- Every drum edit while drum tab is shown re-projects the whole score (follow is off for such a track); this was not measured on a long score.
- Digits cannot be typed on the tab; hits are entered from the drum kit.

## Review findings and their outcome

Three reviews (correctness, interaction, output) found the items below. For each: confirmed by a test that failed before the change, a
coverage gap (the test passes on the old code and was added anyway), or not done.

| Finding | Outcome |
|---|---|
| Ties between differently written hits drawn, wrong "(36)" on the crash | Confirmed; fixed (ties come from `report.ties`, equal number and line only) |
| Tie origin left off the tab made the copy fail to build | Confirmed (TypeError on the old code); fixed (the JSON names no tie partner) |
| Lines assigned per voice, so hands and feet overprint | Confirmed; fixed (lines per moment across the voices of a bar) |
| Dynamics, fermata, volta, directions, tremolo repeated under the tab in standard + tablature | Confirmed by counting glyphs in the SVG; fixed (guard and JSON) |
| Rhythm, time signature and rests repeated on the tab in standard + tablature | Confirmed, not changed; documented above |
| Stale profile of a removed track made the next drum toggle refuse | Confirmed; fixed |
| TAB toggle on a percussion staff of a mixed or two-staff track recorded no-op edits | Confirmed; fixed (inert, says why) |
| Slash style shown as standard in the inspector | Confirmed; fixed |
| Estonian strings called hits "löök" (a beat) | Fixed |
| Which staff of a pair was clicked kept per track index, never cleared | Confirmed; fixed (by identity, cleared per document) |
| Desktop driver read no text from the export hook; Estonian and German shots used English labels | Confirmed by reading the hook; fixed, driver not run |
| Tests used only the default articulation table | Coverage gap; test with a Guitar Pro style table added |
| Error shading in standard + tablature covers only the clicked staff | Not done |
| ArrowUp/ArrowDown steps in storage order, not by drawn line | Not done |
| Print test checks the multiset of numbers, not their lines; tuning header leak | Not done |
| Extra JSON parse and per-edit re-projection cost; `drumTabLeftOff` not memoized | Not done, not measured |
| Adding a staff to a tab-only drum track is refused with a message that does not name drum tab | Not done |
