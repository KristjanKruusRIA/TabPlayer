# Guitar Pro 8 Document Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver W05: independently edited/saved document tabs, one active audio owner, cross-document music clipboard and lossless canceled close workflows.

**Architecture:** Native `DocumentWorkspace` retains isolated `ProjectSession`s; stable document IDs address all file/history/asset/export operations. A narrow activation ID fences audio IPC before existing generation checks. Root stages contracts, workers implement disjoint native/coordination/tab modules, and root joins the existing editor, audio/export runtime and bootstrap.

**Tech Stack:** Existing React/TypeScript, alphaTab 1.8.4, Rust 1.88/Tauri, CPAL, Vitest and Rust tests; no new dependencies.

**Spec:** [2026-10-15-gp8-document-tabs-design.md](../specs/2026-10-15-gp8-document-tabs-design.md)

## Global Constraints

- Native project schema **2**, engine/alphaTab **1.8.4**, Rust **1.88**; existing dependencies only. No dependency patch, frontend history fork, plugin framework or unbound active-document write fallback.
- W05 only. W10/W11 recovery/session restore, W06 templates, W07 recent/pinned files, library/preferences/associations and baseline status/count changes remain separate.
- Live native sessions retain exact source/backing bytes, complete history/cursor/saved comparison and redo-only assets across switches. Ordinary save still compacts applied history/assets; schema-1 migration and schema-2 save compatibility stay intact.
- Stable document IDs address document operations; fresh opaque activation IDs address audio ownership. The activation field never enters callback state, audio status, plans, causal acknowledgements or persisted music.
- One native audio service, one mounted editor/player, one native export slot. Root owns App/main/lib/runtime/bridges, Git, joined suites, builds/apps and native acceptance; workers edit only assigned paths.
- Preserve the approved three columns, slate/cream/lime tokens and physical instrument artwork; add a narrow horizontally scrollable tab row. Use explicit 1-based user labels and zero-based musical addresses.
- Preparation/mix/ordinary audio commands and workspace/export transitions use audio access gate → workspace lock; release workspace before decode/resource work and retain the gate through the service operation. **Only Invalidate bypasses the gate/control/cache:** validate exact owner and call the existing atomic service command while holding workspace lock alone. Transition invalidation and new-owner publication share one gate→workspace critical section. No RwLock, callback lock/allocation or browser transport clock.
- Existing full-goal authorization and parallel execution apply. Do not introduce additional user confirmation/handoff gates; root obtains independent artifact/code review.

## Review Focus

1. A late A save/backing candidate must remain bound to A after B is active, or reject a closed/stale A without consuming B's candidates — Tasks2/4/6.
2. A→B→A with first-A reserved generation100 and native desired10 must reject the first activation before generation atomics, including old invalidate — Tasks6/8.
3. Close All: Discard A then canceled/failed Save B must retain both histories/redo/views and all tabs; earlier successful explicit saves may remain saved — Task5.
4. Canceling export before its native job ID arrives must retain the external-operation lease until cancellation reaches a terminal native result — Tasks6/7.
5. Save As to an inactive tab's native destination or redo-only backing source must preserve every original and both live sessions — Tasks2/6/8.
