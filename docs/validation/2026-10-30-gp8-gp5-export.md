# GP8 parity F10: export a Guitar Pro 5 file (2026-10-30)

GP8 saves older Guitar Pro formats. alphaTab 1.8 ships a Guitar Pro 7 exporter only, so TabPlayer now has a Guitar Pro 5 (`.gp5`, version 5.10) writer of its own. Guitar Pro 6 (`.gpx`) export is not delivered, so the row stays partial. Design: `docs/superpowers/specs/2026-10-24-gp8-gp5-export-design.md`.

## Behavior
- **Export score → Guitar Pro 5** uses the shared track, measure and file-name selection and saves `.gp5`. The dialog says plainly that `.gpx` export is not available.
- **Before anything is saved:**
  - Music whose notes or rhythm the format cannot hold is refused in the dialog and by the coordinator. Examples are more than 7 strings, a string-less track, a partial capo, a transposing instrument, a double-dotted note, a tuplet the format lacks, a numerator above 127, a denominator that is not a power of two, and a pickup that is empty or of an unsayable length.
  - Everything else the format cannot hold is listed in plain words, one line per kind with a count. The existing confirmation repeats the list, and declining stops the export before the save dialog. The dialog says nothing is left out only when the list is empty.
- **Written:** notes, rhythm, tuplets, ties, repeats, endings, sections, directions, tempo and tempo changes (with their text), key and time signatures, up to 7 strings, capo, chord diagrams, lyrics, mixer settings, percussion, and the common techniques. Grace chords are one grace note per string.
- **Pickup measures:** the format has no pickup flag. A pickup is written with a time signature of its own length, so every later note keeps its absolute tick. Its length is the longest bar of any track in the whole score, measured before track and measure selection, so exporting a track whose own pickup bar is empty still keeps the full score's bar starts.
- **Text:** Windows-1252, as Guitar Pro 5 stores it. Text is composed (NFC) first, the sharp and flat signs become `#` and `b`, and a character that codepage lacks becomes `?` and is counted as left out.
- **Native side:** `export_gp5` refuses bytes that are not a Guitar Pro 5 header before it asks for a destination.

## Evidence
- **Unit tests:** `src/export/gp5.test.ts` has 97 tests.
  - **Reader round trip:** every corpus file that reads (`.gp3` to `.gp8`, `.gpx`, `.gp`) is written and read back through alphaTab's GP3-5 reader to the last byte, with equal rhythm in absolute ticks, pitches and techniques. The real Guitar Pro 5.10 sample writes back byte for byte apart from the unused tail of its version field.
  - **Pickups:** read-back bar starts equal the full score's bar starts when only a track with an empty pickup bar is exported, when another track's pickup is longer, and for ranges starting at or after the pickup.
  - **Loss reporting:** one scenario for each kind of loss, and a test that classifies every field of alphaTab's Beat, Note, Bar, MasterBar, Staff, Track, Score, Automation, TremoloPickingEffect and Chord, so a field a later alphaTab adds fails the test until it is written, listed or marked as styling.
- **Dialog and coordinator:** `ExportDialog.test.tsx` checks the "nothing is left out" line appears only when the list is empty. `useExportCoordinator.test.ts` checks the order: refuse, confirm, save.
- **Rust:** `runtime::gp5_tests::only_a_guitar_pro_5_header_is_accepted`.
- **Desktop acceptance:** `tests/desktop/parity-gp5-export.mjs` (written, not run when this was drafted). Evidence for the desktop run is to be added by the controller.

## Review
- **First review:** rejected. The pickup shifted later notes with no report, text was UTF-8 where the format uses a legacy codepage, a tempo change was written twice, dynamics outside ppp to fff became ppp, and many kinds of loss produced an empty list. Fixed in `22d74df`.
- **Second review:** rejected. The pickup was measured on the selection rather than the whole score, a bank change on an empty voice and the mixer changes of a simile measure were not reported, a percussion grace note wrote its fret, tempo text, tremolo style and chord display flags were dropped silently, and text was not normalised. Fixed in the commit that adds this file.

## Limits
- **Not opened in real Guitar Pro.** Every check reads the file back through alphaTab's reader. The meaning of a few bytes (the grace length byte, the whammy type byte) comes from reading the format and the corpus file, not from Guitar Pro.
- **`.gpx` export is not delivered.**
- **Standing losses:** page layout, styling, sound settings and backing audio never survive a `.gp5`. Short track names, tuning preset names, staff line counts, bar-number display and custom beaming are not listed individually.
- **Re-import:** TabPlayer's own importer decodes legacy files as UTF-8 by default, so non-ASCII text in a `.gp5` it wrote is shown differently when re-imported there.
- **Grace notes:** a grace length is stored as one of two values (a 64th, or the usual 32nd), taken from the size of the grace group.
