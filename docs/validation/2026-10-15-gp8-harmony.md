# Harmony tools validation

Date: 2026-10-15. Branch `feat/gp8-parity`; released `main` remains `7fc41c7`. The full parity goal remains active; this report does not change historical baseline counts.

## Delivered behavior

The chord editor supports 22 formulas, spelled roots/alterations/omissions/slash bass, deterministic bounded shape search, sounding-pitch recognition, explicit frets/fingers/barres and display flags. Owned theory recipes are validated against the actual tuning, capo and sounding offset. Manual and legacy diagrams retain their passive snapshot domain. A stale instrument context downgrades the effective chord to manual while preserving raw provenance for history restoration. Text-only edits preserve existing rich chord definitions.

The scale browser provides 16 named patterns, all 12 roots, search/tags, custom sorted intervals, passage matching and a selected-staff fretboard/keyboard preview. Browsing changes no music or history. Harmony transposition supports signed semitones, named chromatic intervals and diatonic key-relative steps as one atomic history command. Complete-bar/all-track and complete-beat checks govern optional key/theory-chord changes; percussion and manual/context-changed chord handling remain explicit.

The personal chord library is independent native app-data storage with UUID identity, strict validation and atomic read/put/remove operations. Matching-context recall preserves the saved snapshot; valid theory recipes can search a destination shape. No caller supplies a filesystem path. Operation revisions prevent a late old dialog response from replacing a newer library snapshot. New/Open and process restart retain personal entries. Clipboard v1 remains unchanged; v2 carries only referenced rich harmony records with exact context validation, deep cloning and self-contained replay.

GP interchange reads/writes demonstrated standard diagram/finger/display fields and retains source provenance through cloning, excerpting, reordering, pitched normalization and export. Theory recipes remain native-only. The public writer omits cached-empty Voice references, orphaning their chord-bearing beats. For one existing plain-quarter empty carrier only, export uses a detached clone and represents that carrier as a silent explicit quarter rest. Native emptiness and source remain exact; the GP carrier voice duration changes from 0 to 960 ticks. Master-bar/sounding clocks and independently decoded MIDI events/end ticks remain exact. Unsupported carrier configurations or a clock-extending pickup reject visibly before file writing. This is an explicit GP representation limit.

## Remaining scope

This is not full GP chord/scale catalogue, audition, scale insertion or notation-format parity. Diatonic chord/key transposition, out-of-key chromatic-alteration policy and unrepresentable spellings/shapes reject explicitly. GP recipe roundtrip and independently unrepresentable finger/barre combinations remain unsupported; native snapshots are the preservation format. A malformed direct-JavaScript array with named object properties can pass one frontend exact-object predicate but serializes to an array that native safely rejects; this minor discrepancy is explicitly deferred and is not constructible by ordinary JSON/UI input. Original GP8 runtime, physical macOS/Linux and broader sound/engraving parity remain unverified. No shipping installer or `main` integration is claimed here.
